# Execution V2 source audit

Audited 2026-08-26. Current below means the cited official repository commit, pinned by full SHA. The first mapping covers append-only execution facts, derived state, bounded model context, and exact decision-request fidelity. The durable extension covers persistent root identity, durable EventLog/checkpoint recovery, and WAIT/event/resume. It does not authorize importing any source's larger runtime architecture.

## OpenAI Codex

- **SOURCE / COMMIT / VERSION / LICENSE:** [openai/codex at `a9ed4f154a4fad64acf538d6418d3ed012aeab86`](https://github.com/openai/codex/tree/a9ed4f154a4fad64acf538d6418d3ed012aeab86), rolling `main` (`codex-rs` workspace version `0.0.0` at this commit); [Apache-2.0](https://github.com/openai/codex/blob/a9ed4f154a4fad64acf538d6418d3ed012aeab86/LICENSE). The full commit, not the placeholder workspace version, is the audited version.
- **SOURCE SYMBOL / PATH:** [`Session` / `SessionConfiguration`](https://github.com/openai/codex/blob/a9ed4f154a4fad64acf538d6418d3ed012aeab86/codex-rs/core/src/session/session.rs), [`TurnContext` / `make_turn_context`](https://github.com/openai/codex/blob/a9ed4f154a4fad64acf538d6418d3ed012aeab86/codex-rs/core/src/session/turn_context.rs), [`StepContext`](https://github.com/openai/codex/blob/a9ed4f154a4fad64acf538d6418d3ed012aeab86/codex-rs/core/src/session/step_context.rs), [`run_turn` / `run_sampling_request`](https://github.com/openai/codex/blob/a9ed4f154a4fad64acf538d6418d3ed012aeab86/codex-rs/core/src/session/turn.rs), [`ToolRouter::model_visible_specs`](https://github.com/openai/codex/blob/a9ed4f154a4fad64acf538d6418d3ed012aeab86/codex-rs/core/src/tools/router.rs), [`Prompt`](https://github.com/openai/codex/blob/a9ed4f154a4fad64acf538d6418d3ed012aeab86/codex-rs/core/src/client_common.rs), and [`ExecCommandToolOutput::response_text` / `truncated_output`](https://github.com/openai/codex/blob/a9ed4f154a4fad64acf538d6418d3ed012aeab86/codex-rs/core/src/tools/context.rs).
- **ORIGINAL INPUT / OUTPUT OR CONTRACT:** `TurnContext` holds turn-scoped configuration. `StepContext` is explicitly request-scoped and freezes the concrete model, environment, approvals, capability roots, MCP bindings, loaded instructions, and the finalized `ToolRouter` for one sampling request. `run_turn` captures that context once so prompt construction, advertised tools, and subsequent tool dispatch share the same request view. `Prompt` is the single-model-turn payload. Tool execution retains raw output while `response_text()` creates a bounded model-visible form with an explicit truncation warning and original token count.
- **BEHAVIOR BORROWED:** Capture one immutable request view before sampling; derive both the advertised tools and the provider payload from it; keep canonical tool facts distinct from their bounded model-visible projection.
- **LUMINA ADAPTATION:** Build the bounded `Context` and available-tool list first, pass that exact request object to `Model.decide`, then create the immutable `DecisionFrame` from the same request plus the returned response/action. A truncation marker is part of the request text whenever canonical output is shortened.
- **BEHAVIOR NOT COPIED:** Codex's session/task machinery, approvals, MCP/capability discovery, provider stack, async task lifecycle, and tool router. Codex does not supply a durable Lumina `DecisionFrame` contract; exact `actual_request` persistence is a Lumina boundary, not a claimed Codex feature.
- **DURABLE SOURCE SYMBOL / PATH:** [`thread-store` durable-handle contract](https://github.com/openai/codex/blob/a9ed4f154a4fad64acf538d6418d3ed012aeab86/codex-rs/thread-store/src/lib.rs), [`CreateThreadParams` / `ResumeThreadParams` / `StoredThreadHistory` / `StoredModelContext`](https://github.com/openai/codex/blob/a9ed4f154a4fad64acf538d6418d3ed012aeab86/codex-rs/thread-store/src/types.rs), [`LiveThread::resume` / `append_items` / `flush`](https://github.com/openai/codex/blob/a9ed4f154a4fad64acf538d6418d3ed012aeab86/codex-rs/thread-store/src/live_thread.rs), [`ThreadManager::resume_thread_with_history`](https://github.com/openai/codex/blob/a9ed4f154a4fad64acf538d6418d3ed012aeab86/codex-rs/core/src/thread_manager.rs), [`RolloutRecorder::persist` / `flush`](https://github.com/openai/codex/blob/a9ed4f154a4fad64acf538d6418d3ed012aeab86/codex-rs/rollout/src/recorder.rs), and the [`thread/resume`, `turn/start`, `turn/interrupt` lifecycle](https://github.com/openai/codex/blob/a9ed4f154a4fad64acf538d6418d3ed012aeab86/codex-rs/app-server/README.md).
- **DURABLE ORIGINAL BEHAVIOR (DIRECT FACT):** Codex says application code should treat `ThreadId` as its only durable thread handle. `CreateThreadParams` receives a thread id before opening persistence; `ResumeThreadParams` reopens that existing id for future appends. Stored history/model context remains in replay order. A runtime `Session` has at most one active task and can be interrupted; resuming uses the persisted conversation id and `LiveThread::resume`. `RolloutRecorder::flush` waits for queued writes, while `persist` materializes buffered rollout data and is idempotent.
- **DURABLE BEHAVIOR BORROWED / LUMINA ADAPTATION:** Separate long-lived identity from process, turn, and request lifetimes. Lumina persists `execution_id` and its one `root_actor_id`; a fresh Runtime reopens those ids and reconstructs state from durable facts before any new model call. `Checkpoint` accelerates that reconstruction but does not replace the EventLog.
- **DURABLE BEHAVIOR DELIBERATELY NOT COPIED:** Codex thread trees, `SessionId` ancestry, forks/subagents, rollout schema, app-server protocol, archive/delete/rollback, active-writer ownership, approval persistence, and its complete resume framework. Mapping Codex `ThreadId` to Lumina `execution_id` is an adaptation, not identity or format compatibility.

## DeepSeek Harness (DSH)

- **SOURCE / COMMIT / VERSION / LICENSE:** [deepseek-ai/deepseek-harness at `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`](https://github.com/deepseek-ai/deepseek-harness/tree/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e), `dsh 0.1.1-rc.2`; [MIT](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/LICENSE).
- **SOURCE SYMBOL / PATH:** [Session subsystem contract](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/docs/subsystems/session.md), [`SessionEventMap` / `SessionEvent` / `sourceEventSeqs`](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/core/session/src/types.ts), [`Session.append` / `deriveMessages` / `deriveEventMessage`](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/core/session/src/index.ts), [`foldSurface`](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/core/session/src/surface.ts), and [`SessionPersistence`](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/session/session-persistence/src/index.ts).
- **ORIGINAL INPUT / OUTPUT OR CONTRACT:** A `Session` is an append-only typed `SessionEvent` log and the single source of truth; model messages are derived, not separately authoritative. `append` assigns the next monotonic `seq`, snapshots/freezes and validates the event, then commits it. `sourceEventSeqs` cites earlier causal events—for example, an assistant message cites its streamed chunks and a tool result cites its tool call. `deriveMessages()` folds the log into the current model-visible surface. Persistence stores the existing event type contiguously and losslessly; it does not introduce a parallel persisted fact model.
- **BEHAVIOR BORROWED:** Append immutable facts with a stable sequence; derive working/model state by a pure fold; use explicit source-event references when a derived fact needs causal provenance.
- **LUMINA ADAPTATION:** Use the smallest fixed `Event` vocabulary needed by this slice and derive `ExecutionState` from the ordered tuple on demand. Preserve event identity/provenance in state and decision records; never mutate history to represent progress.
- **BEHAVIOR NOT COPIED:** DSH's extensible session ontology, surface replacement/compaction operations, streaming chunk graph, plugin hooks, and full agent loop. The audited DSH package is pre-release, and its persistence format is separately marked format version `0`; neither becomes a Lumina compatibility promise.
- **DURABLE SOURCE SYMBOL / PATH:** [`SessionPersistence.append` / `prepare` / `load`](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/session/session-persistence/src/index.ts), [`SessionWriteBehind.flush`](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/session/session-persistence/src/write-behind.ts), [`session-checkpoint-policy`](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/session/session-checkpoint-policy/src/index.ts), [`interruptedTurnClosers`](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/core/session/src/repair.ts), and the [persistence/flush/recovery contract](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/docs/subsystems/persistence.md).
- **DURABLE ORIGINAL BEHAVIOR (DIRECT FACT):** The durable unit remains the existing contiguous `SessionEvent`; there is no second persisted-message authority. In-memory `Session.append` commits synchronously and persistence observes it asynchronously through write-behind batching. `SessionWriteBehind.flush` cancels the batching wait and drains to quiescence; the checkpoint policy flushes before model dispatch and top-level tool dispatch. Cold load reconstructs the event log and appends deterministic interruption closers for an open tail turn. Committed corruption rejects, while only an incomplete final physical record may be discarded. `sourceEventSeqs` continues to identify earlier causal events.
- **DURABLE BEHAVIOR BORROWED / LUMINA ADAPTATION:** Persist the canonical event envelope itself; derive model-visible history and recovered state from that durable sequence; expose an explicit durability barrier before the next decision/effect boundary. Lumina deliberately strengthens DSH's hot-path ordering: `EventLog.append` is not authoritative until its local append-and-flush succeeds, so no accepted in-memory event can outrun the durable log. Lumina's materialized `Checkpoint` is a replay optimization, not DSH's semantic flush checkpoint.
- **DURABLE BEHAVIOR DELIBERATELY NOT COPIED:** Write-behind batching, service/plugin seams, JSONL compression, SQLite, session preparation/publication, surface repair, and synthetic unknown-outcome tool results. `interruptedTurnClosers` explicitly addresses a side-effect uncertainty window; this Lumina slice permits restart only after a durably settled action or at WAIT and does not reconcile UNKNOWN effects.

- **SOURCE SYMBOL / PATH:** [core agent contract](https://github.com/PrimeIntellect-ai/prime-agent/blob/514633727bf26d74f39f3119c2b0e31a5ceb2a9d/packages/agent/README.md), [`Agent`](https://github.com/PrimeIntellect-ai/prime-agent/blob/514633727bf26d74f39f3119c2b0e31a5ceb2a9d/packages/agent/src/agent.ts), [`runAgentLoop` / `runAgentLoopContinue`](https://github.com/PrimeIntellect-ai/prime-agent/blob/514633727bf26d74f39f3119c2b0e31a5ceb2a9d/packages/agent/src/agent-loop.ts), and [`AgentContext` / `AgentState` / `AgentTool` / `StreamFn`](https://github.com/PrimeIntellect-ai/prime-agent/blob/514633727bf26d74f39f3119c2b0e31a5ceb2a9d/packages/agent/src/types.ts).
- **ORIGINAL INPUT / OUTPUT OR CONTRACT:** The documented model path is `AgentMessage[] -> transformContext() -> AgentMessage[] -> convertToLlm() -> Message[] -> LLM`: working messages and provider-visible messages are distinct projections. `AgentTool.execute` is a host callback; the loop invokes it and returns the outcome as a tool-result message. The low-level loop accepts an `AgentContext` plus configuration/provider stream function, exposing request/response and before/after-tool boundaries to the host.
- **BEHAVIOR BORROWED:** Keep authoritative side effects in host callbacks, and make agent-visible working/control state an input projection rather than authority. The “host owns execution” characterization is an inference from the official loop and `AgentTool.execute` contracts, not an explicit append-only guarantee in Prime Agent.
- **LUMINA ADAPTATION:** `ToolHost` alone executes a selected tool; `RootAgentProcess` appends the resulting fact, and the model can propose only a decision. The exact provider request and returned response are captured together at the boundary in `DecisionFrame`, while `ExecutionState` remains derived from facts.
- **BEHAVIOR NOT COPIED:** Prime Agent's mutable `AgentState`, persistent IPython/RLM execution, daemon/session infrastructure, extensions, branching, provider abstraction stack, and general coding-agent loop. Prime Agent is not used as evidence for append-only history or durable decision fidelity.
- **DURABLE SOURCE SYMBOL / PATH:** [`AgentSession` and `sessionId`](https://github.com/PrimeIntellect-ai/prime-agent/blob/514633727bf26d74f39f3119c2b0e31a5ceb2a9d/packages/coding-agent/src/core/agent-session.ts), [`AgentSessionRuntime.switchSession` / `teardownForReplacement` / `buildAndApplyReplacement`](https://github.com/PrimeIntellect-ai/prime-agent/blob/514633727bf26d74f39f3119c2b0e31a5ceb2a9d/packages/coding-agent/src/core/agent-session-runtime.ts), [`SessionManager.create` / `open` / `newSession` / `flushNow` / `buildSessionContext`](https://github.com/PrimeIntellect-ai/prime-agent/blob/514633727bf26d74f39f3119c2b0e31a5ceb2a9d/packages/coding-agent/src/core/session-manager.ts), and the [SDK lifecycle contract](https://github.com/PrimeIntellect-ai/prime-agent/blob/514633727bf26d74f39f3119c2b0e31a5ceb2a9d/packages/coding-agent/docs/sdk.md).
- **DURABLE ORIGINAL BEHAVIOR (DIRECT FACT):** `AgentSession` owns one live agent's messages/model/event lifecycle and obtains `sessionId` from `SessionManager`. Session replacement lives one layer out in `AgentSessionRuntime`: `switchSession` opens a persisted manager, tears down the old session, creates a replacement with `reason: resume`, then rebinds it. `SessionManager` stores the id in the JSONL header and `buildSessionContext` reconstructs model-facing messages from the selected persisted branch. `flushNow` forces pre-model state to disk.
- **DURABLE BEHAVIOR BORROWED / LUMINA ADAPTATION:** A live agent object is replaceable; persistent identity and reconstructable history sit at the host boundary. Lumina applies that separation to one Root: Runtime and `RootAgentProcess` objects may disappear, while `execution_id`, `root_actor_id`, durable events, and checkpoint metadata survive and are loaded before a new process is allowed to decide.
- **DURABLE BEHAVIOR DELIBERATELY NOT COPIED:** Prime's `AgentSessionRuntime`, session replacement leases, tree/branch JSONL schema, session migration, compaction, daemon/worker continuity, extensions, and IPython/RLM. **Inference:** Prime's placement of replacement in `AgentSessionRuntime` supports a host-lifecycle reading, but Prime does not state the Lumina rule that working `AgentState` can never be persistence authority.

## Slice-level conclusions

The first-slice mapping remains: DSH-style append-only facts and pure derivation; Codex-style request-scoped tool/context snapshot and explicit bounded projection; Prime-style host-controlled tool execution; and LongHorizon's separation of evidence from derived/verified state. `DecisionFrame.actual_request` remains Lumina-specific: it is the exact bounded request object supplied to `Model.decide`, never a later reconstruction.

The durable extension is deliberately smaller than every upstream: Codex contributes identity/lifecycle separation; DSH contributes canonical-event persistence and explicit flush/reconstruction boundaries; Prime contributes replaceable live-session semantics under a host; LongHorizon contributes recovery from recorded facts instead of old model control flow; Temporal contributes durable event-driven wake and the warning that committed results do not solve an unrecorded external-effect window. Lumina keeps one Root, a durable-first local EventLog, a non-authoritative checkpoint validated against replay, zero model sampling while WAITING, typed mechanical wake, and no replay of durably completed actions.

## Source ambiguities and non-equivalences

- **Direct source fact:** every positive upstream behavior above names a pinned symbol or official contract. **Inference** is marked explicitly for Prime's host-authority reading and Temporal's wake shorthand.
- Codex rolling `main` moved since the first audit; the new full SHA is the reproducibility pin. Its identifiers and rollout format are not Lumina formats.
- DSH commits to the in-memory log before asynchronous persistence and relies on explicit flush barriers. Lumina's task contract is stricter: persistence succeeds before an event becomes authoritative.
- LongHorizon recovery skips malformed ledger lines and has no audited generic serialized-checkpoint symbol. Lumina instead fails malformed history/corrupt checkpoints and treats its checkpoint as a local replay optimization.
- Temporal guarantees deterministic Workflow replay against durable history, not exactly-once arbitrary external side effects. This audit does not authorize UNKNOWN-effect reconciliation.
