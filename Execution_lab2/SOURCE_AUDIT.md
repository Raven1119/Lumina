# Execution V2 source audit

Audited 2026-08-26. “Current” below means the cited official repository commit, pinned by full SHA. This audit covers only the approved slice: append-only execution facts, a derived state fold, bounded model context, and fidelity of the actual decision request. It does not authorize importing any source's larger runtime architecture.

## OpenAI Codex

- **SOURCE / VERSION / LICENSE:** [openai/codex at `3ba7b6941d3caf6eec5b3c4e564988ee57d3f083`](https://github.com/openai/codex/tree/3ba7b6941d3caf6eec5b3c4e564988ee57d3f083), rolling `main`; [Apache-2.0](https://github.com/openai/codex/blob/3ba7b6941d3caf6eec5b3c4e564988ee57d3f083/LICENSE). No release number is assigned here: the full commit is the audited version.
- **SOURCE SYMBOL / PATH:** [`Session` / `SessionConfiguration`](https://github.com/openai/codex/blob/3ba7b6941d3caf6eec5b3c4e564988ee57d3f083/codex-rs/core/src/session/session.rs), [`TurnContext` / `make_turn_context`](https://github.com/openai/codex/blob/3ba7b6941d3caf6eec5b3c4e564988ee57d3f083/codex-rs/core/src/session/turn_context.rs), [`StepContext`](https://github.com/openai/codex/blob/3ba7b6941d3caf6eec5b3c4e564988ee57d3f083/codex-rs/core/src/session/step_context.rs), [`run_turn` / `run_sampling_request`](https://github.com/openai/codex/blob/3ba7b6941d3caf6eec5b3c4e564988ee57d3f083/codex-rs/core/src/session/turn.rs), [`ToolRouter::model_visible_specs`](https://github.com/openai/codex/blob/3ba7b6941d3caf6eec5b3c4e564988ee57d3f083/codex-rs/core/src/tools/router.rs), [`Prompt`](https://github.com/openai/codex/blob/3ba7b6941d3caf6eec5b3c4e564988ee57d3f083/codex-rs/core/src/client_common.rs), and [`ExecCommandToolOutput::response_text` / `truncated_output`](https://github.com/openai/codex/blob/3ba7b6941d3caf6eec5b3c4e564988ee57d3f083/codex-rs/core/src/tools/context.rs).
- **ORIGINAL INPUT / OUTPUT OR CONTRACT:** `TurnContext` holds turn-scoped configuration. `StepContext` is explicitly request-scoped and freezes the concrete model, environment, approvals, capability roots, MCP bindings, loaded instructions, and the finalized `ToolRouter` for one sampling request. `run_turn` captures that context once so prompt construction, advertised tools, and subsequent tool dispatch share the same request view. `Prompt` is the single-model-turn payload. Tool execution retains raw output while `response_text()` creates a bounded model-visible form with an explicit truncation warning and original token count.
- **BEHAVIOR BORROWED:** Capture one immutable request view before sampling; derive both the advertised tools and the provider payload from it; keep canonical tool facts distinct from their bounded model-visible projection.
- **LUMINA ADAPTATION:** Build the bounded `Context` and available-tool list first, pass that exact request object to `Model.decide`, then create the immutable `DecisionFrame` from the same request plus the returned response/action. A truncation marker is part of the request text whenever canonical output is shortened.
- **BEHAVIOR NOT COPIED:** Codex's session/task machinery, approvals, MCP/capability discovery, provider stack, async task lifecycle, and tool router. Codex does not supply a durable Lumina `DecisionFrame` contract; exact `actual_request` persistence is a Lumina boundary, not a claimed Codex feature.

## DeepSeek Harness (DSH)

- **SOURCE / VERSION / LICENSE:** [deepseek-ai/deepseek-harness at `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`](https://github.com/deepseek-ai/deepseek-harness/tree/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e), `dsh 0.1.1-rc.2`; [MIT](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/LICENSE).
- **SOURCE SYMBOL / PATH:** [Session subsystem contract](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/docs/subsystems/session.md), [`SessionEventMap` / `SessionEvent` / `sourceEventSeqs`](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/core/session/src/types.ts), [`Session.append` / `deriveMessages` / `deriveEventMessage`](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/core/session/src/index.ts), [`foldSurface`](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/core/session/src/surface.ts), and [`SessionPersistence`](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/session/session-persistence/src/index.ts).
- **ORIGINAL INPUT / OUTPUT OR CONTRACT:** A `Session` is an append-only typed `SessionEvent` log and the single source of truth; model messages are derived, not separately authoritative. `append` assigns the next monotonic `seq`, snapshots/freezes and validates the event, then commits it. `sourceEventSeqs` cites earlier causal events—for example, an assistant message cites its streamed chunks and a tool result cites its tool call. `deriveMessages()` folds the log into the current model-visible surface. Persistence stores the existing event type contiguously and losslessly; it does not introduce a parallel persisted fact model.
- **BEHAVIOR BORROWED:** Append immutable facts with a stable sequence; derive working/model state by a pure fold; use explicit source-event references when a derived fact needs causal provenance.
- **LUMINA ADAPTATION:** Use the smallest fixed `Event` vocabulary needed by this slice and derive `ExecutionState` from the ordered tuple on demand. Preserve event identity/provenance in state and decision records; never mutate history to represent progress.
- **BEHAVIOR NOT COPIED:** DSH's extensible session ontology, surface replacement/compaction operations, streaming chunk graph, plugin hooks, JSONL/SQLite persistence, durability/recovery protocol, and full agent loop. The audited DSH package is pre-release, and its persistence format is separately marked format version `0`; neither becomes a Lumina compatibility promise.

## Prime Agent

- **SOURCE / VERSION / LICENSE:** [PrimeIntellect-ai/prime-agent at `514633727bf26d74f39f3119c2b0e31a5ceb2a9d`](https://github.com/PrimeIntellect-ai/prime-agent/tree/514633727bf26d74f39f3119c2b0e31a5ceb2a9d), `v0.8.1`; [MIT](https://github.com/PrimeIntellect-ai/prime-agent/blob/514633727bf26d74f39f3119c2b0e31a5ceb2a9d/LICENSE).
- **SOURCE SYMBOL / PATH:** [core agent contract](https://github.com/PrimeIntellect-ai/prime-agent/blob/514633727bf26d74f39f3119c2b0e31a5ceb2a9d/packages/agent/README.md), [`Agent`](https://github.com/PrimeIntellect-ai/prime-agent/blob/514633727bf26d74f39f3119c2b0e31a5ceb2a9d/packages/agent/src/agent.ts), [`runAgentLoop` / `runAgentLoopContinue`](https://github.com/PrimeIntellect-ai/prime-agent/blob/514633727bf26d74f39f3119c2b0e31a5ceb2a9d/packages/agent/src/agent-loop.ts), and [`AgentContext` / `AgentState` / `AgentTool` / `StreamFn`](https://github.com/PrimeIntellect-ai/prime-agent/blob/514633727bf26d74f39f3119c2b0e31a5ceb2a9d/packages/agent/src/types.ts).
- **ORIGINAL INPUT / OUTPUT OR CONTRACT:** The documented model path is `AgentMessage[] -> transformContext() -> AgentMessage[] -> convertToLlm() -> Message[] -> LLM`: working messages and provider-visible messages are distinct projections. `AgentTool.execute` is a host callback; the loop invokes it and returns the outcome as a tool-result message. The low-level loop accepts an `AgentContext` plus configuration/provider stream function, exposing request/response and before/after-tool boundaries to the host.
- **BEHAVIOR BORROWED:** Keep authoritative side effects in host callbacks, and make agent-visible working/control state an input projection rather than authority. The “host owns execution” characterization is an inference from the official loop and `AgentTool.execute` contracts, not an explicit append-only guarantee in Prime Agent.
- **LUMINA ADAPTATION:** `ToolHost` alone executes a selected tool; `RootAgentProcess` appends the resulting fact, and the model can propose only a decision. The exact provider request and returned response are captured together at the boundary in `DecisionFrame`, while `ExecutionState` remains derived from facts.
- **BEHAVIOR NOT COPIED:** Prime Agent's mutable `AgentState`, persistent IPython/RLM execution, daemon/session infrastructure, extensions, branching, provider abstraction stack, and general coding-agent loop. Prime Agent is not used as evidence for append-only history or durable decision fidelity.

## LongHorizon-Harness

- **SOURCE / VERSION / LICENSE:** [AMAP-ML/LongHorizon-Harness at `a1dd930614972b92361c1b9cd6aac441a6db5a65`](https://github.com/AMAP-ML/LongHorizon-Harness/tree/a1dd930614972b92361c1b9cd6aac441a6db5a65), `v0.1.7`; [MIT](https://github.com/AMAP-ML/LongHorizon-Harness/blob/a1dd930614972b92361c1b9cd6aac441a6db5a65/LICENSE).
- **SOURCE SYMBOL / PATH:** [run-record and role contract](https://github.com/AMAP-ML/LongHorizon-Harness/blob/a1dd930614972b92361c1b9cd6aac441a6db5a65/README.md), [`EpisodeResult` / `AuditReport` / `ManagedRound`](https://github.com/AMAP-ML/LongHorizon-Harness/blob/a1dd930614972b92361c1b9cd6aac441a6db5a65/src/lh_harness/types.py), [`ManagerAgent._run_impl` / `_record_round` / `_append_event`](https://github.com/AMAP-ML/LongHorizon-Harness/blob/a1dd930614972b92361c1b9cd6aac441a6db5a65/src/lh_harness/manager.py), and [`audit_report_from_episode_result` / `parse_audit_report`](https://github.com/AMAP-ML/LongHorizon-Harness/blob/a1dd930614972b92361c1b9cd6aac441a6db5a65/src/lh_harness/auditor_agent.py).
- **ORIGINAL INPUT / OUTPUT OR CONTRACT:** Each isolated run retains an event stream, task state, role trajectories, workspace, audits, and final report. `EpisodeResult` records an execution episode; `AuditReport` is a structured verification result; `ManagedRound` combines plan, executor output, audit, feedback, and derived task state. Resume reconstructs manager input from recorded rounds and verified task state rather than replaying raw prior prompts. A task is complete only when the latest independent audit is cleanly complete; rejected work remains evidence rather than progress.
- **BEHAVIOR BORROWED:** Preserve the distinction between execution evidence, derived progress state, and verification conclusions. Recovery and verification are useful evidence that these layers must not be conflated.
- **LUMINA ADAPTATION:** For this first slice, raw `EventLog` facts remain authoritative and `ExecutionState` is only their deterministic projection. Any result/verification fact must be appended before it can affect the fold.
- **BEHAVIOR NOT COPIED:** Manager/Executor/Auditor roles, checkpoints, resume/recovery, multi-round orchestration, dashboards, role prompts, external-process control, and independent verifier implementation. They are explicitly outside this vertical slice.

## Slice-level conclusion

The narrow composite is: DSH-style append-only facts and pure derivation; Codex-style request-scoped tool/context snapshot and explicit bounded projection; Prime-style host-controlled tool execution; and LongHorizon's separation of evidence from derived/verified state. `DecisionFrame.actual_request` remains a Lumina-specific invariant: it must be the exact bounded request object actually supplied to `Model.decide`, not a later reconstruction. None of the audited sources justifies persistence, recovery, checkpoints, child agents, background processes, or a larger orchestration framework in this slice.
