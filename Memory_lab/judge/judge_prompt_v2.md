# 回答层盲评 v2：证据包

输入 JSON 包含 `items`；不提供完整对话记录。每个 item 是某个时刻他发来的一条消息、两个候选回复 X/Y，以及 `证据轮次`。证据按时间排序，每行有轮次 ID、日期、时间和说话人；它包含当时 Hot 的最后 6 轮、出题人的金标准与干扰轮次及附近轮次、两个回答内容相近的过去轮次。证据经过抽样，可能漏掉真实往事。X 和 Y 来自两个不同系统，身份与顺序未知。

林素的人设：冷静、克制、简洁；关心体现在记住细节和给出可靠的建议上；不卖萌，不空泛安慰。回复简短是人设，不因简短扣分。

对每个条目：

1. 对照 `证据轮次` 核实 X、Y 中每一个关于过去的说法（谁、什么事、哪天、结果如何）。
2. 分别给 X 和 Y 打分：
   - `should`：`评分要点.should` 的每一条，做到给 1，部分做到给 0.5，没做到给 0。要点是“正常回应”的，只要回复正常、得体就给 1。
   - `should_not`：`评分要点.should_not` 的每一条，出现给 1，没出现给 0。
   - `wrong`：回复里关于过去的说法被证据反驳，或明显无中生有，才给 true，并在 `note` 里写出是哪一句、错在哪。证据里找不到、也没有矛盾的说法，不算说错。带疑问语气的合理询问或推测不算。
   - `alive`：1–5 分，衡量像不像一个真正记得他、了解他的人在回应。标准：该用上的往事自然用上，接得上前文，不硬扯无关的旧事，不遗忘关键事实，不编造。5 分为非常像；3 分为普通得体，但看不出记得什么；1 分为明显出错或不合时宜。
3. `prefer`：整体上哪个回复更好，填 `X`、`Y` 或 `tie`，`reason` 用一句话说明。只有两者实质相同或优劣相抵时才选 tie。

`说明` 字段注明“60 天后”的条目：他在最后一轮对话之后 60 多天没有说话，才发来这条消息。这时提起很久以前一次性聊过的闲聊细节，通常不自然。

`相关事实` 和 `出题人备注` 是出题人的标注，帮助你理解这条消息想测什么；判断对错以 `证据轮次` 为准，并遵守上面的证据不足规则。

只输出一个 JSON 对象，格式为 `{"items":[{"id":"...","X":{"should":[1],"should_not":[],"wrong":false,"note":"","alive":4},"Y":{"should":[0.5],"should_not":[],"wrong":true,"note":"...","alive":2},"prefer":"X","reason":"..."}]}`。输出应只包含输入批次的条目，ID 原样保留，顺序不限。`should` 和 `should_not` 数组长度要分别等于该条目的评分要点数。不要输出系统身份、解释文字或 Markdown。
