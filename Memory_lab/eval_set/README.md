# Conversation Memory 评估集

用来自动评测新记忆系统的两个目标：**联想**与**活人感**（类人的连续性与抽象理解）。
三份第一人称、跨 6 周、低信息密度的对话剧本，每份 30 条带时间戳的探针，共 90 条。
人物与事件全部虚构，不含任何真实对话。

| 集合 | 用途 | 人物 |
| --- | --- | --- |
| dev-a | 开发集 | 生物学博士生，细胞实验常到深夜，养猫 |
| dev-b | 开发集 | 自由插画师，接外包，养狗 |
| holdout-c | 保留集 | 高三物理老师，周末修摩托车 |

**保留集只在最终报告时跑一次，不能用来调参数或改提示词。**

## 目录

```
eval_set/
  build.py                 构建与校验（只用标准库）
  scripts/<set>.txt        对话剧本（手写，行尾带金标准标注）
  gold/<set>.json          植入说明与探针（手写）
  built/<set>.dialogue.json  构建产物：给被测系统的对话，不含任何标注
  built/<set>.gold.json      构建产物：给评测器的金标准，标注已解析成轮次 ID
```

运行 `python build.py` 会构建并校验全部集合，有错误时以非零状态退出。

## 剧本格式

```
@id: dev-a
@split: dev
## s03 2026-03-04 23:50
U: 今晚抢到成像机时了，十点到一点 {#imaging-s03 #habit-late}
L: 恭喜。这台机器白天很难约？
```

- `## <会话ID> <日期> <时:分>` 开始一次对话，时区固定为 +08:00。
- `U:` 是用户，`L:` 是 Lumina；严格交替，由用户开头、以 Lumina 结尾。
- 行尾 `{#标签 ...}` 是金标准标注，构建时剥离。
- 轮次 ID 为 `<会话ID>-tNN`。每轮的时间由构建脚本确定性生成：Lumina 在用户之后 10–59 秒回复，用户下一句在 30–209 秒之后。

## 金标准格式

`plants`：植入了什么。每项列出标签、类型和一句说明，供人阅读，也是评判模型理解探针意图的依据。

`probes`：在某个模拟时刻发出的一条消息，以及期望。

| 字段 | 含义 |
| --- | --- |
| `time` | 探针时刻，`YYYY-MM-DD HH:MM`，+08:00 |
| `message` | 用户在该时刻发来的消息 |
| `category` | 理解当下 / 时间 / 实体 / 远联想 / 接续 / 变化 / 否定 / 自己的看法 / 淡忘 / 保留 / 对照 |
| `must_surface` | 若干组标签；每组至少要有一轮被召回覆盖 |
| `must_not_surface` | 干扰标签；不应“只凭它们”被召回 |
| `rubric.should` / `rubric.should_not` | 回答层评判要点 |
| `soft` | 加分项探针（例如只靠共现才能想到的联想），单独统计 |
| `gap_variants` | 在探针时刻上再加 `offset_days` 天重测，历史不变；可覆盖期望，用来测淡忘与保留 |

构建后的 `built/<set>.gold.json` 把标签解析成探针时刻之前的轮次 ID，并附两项诊断：

- `hot_visible_gold`：探针时刻仍在 Hot 里的金标准轮次。构建时按 Hot 的规则（原文超过 24 轮就压缩，保留最近 12 轮，按完整一问一答对齐）模拟。如果某条探针的每组金标准都还在 Hot 里，构建会直接报错，因为这样的探针测不到记忆。
- `raw_window_gold`：不在 Hot、但在 14 天原文窗口内的金标准轮次。用来区分命中是靠原文窗口还是靠记忆。

## 评测器怎么用

1. **回放**：用模拟时钟按 `time` 逐轮写入 Hot，按原有规则压缩进 Cold，Cold 的新增量达到阈值就触发 Dream。系统内所有取时间的地方都读这个时钟。
2. **探针**：在 `probe.time` 对当前状态开一个只读分支，用 `message` 做一次召回和回答。探针不写回历史，也不写召回痕迹，不影响后续探针。
3. **时间变换**：`gap_variants` 把探针时刻后移 `offset_days`，历史不变。评测器也可以整体平移或拉伸剧本时间戳，用来做淡忘曲线。
4. **缓存**：Dream 响应以窗口内容、提示词版本、模型为键缓存。只改召回侧，或只改探针时刻时，都复用缓存。

## 记忆层打分（确定性，不用模型）

设 S 为一次召回实际交给回答模型的全部来源轮次：每条被召回记忆的 `sources`，加上从原文窗口直接取回的轮次。

- **组命中**：S 与该组任一轮次相交。严格口径要求轮次精确相同；宽松口径允许同一会话内相差 ±2 轮。
- **完全命中**：探针的所有组都命中。
- **只命中干扰**：一条被召回的记忆，其来源与 `must_not_surface` 相交，且与所有 `must_surface` 都不相交。合并后的记忆同时含有正确来源和干扰来源时，不计入干扰。
- **汇总**：按类别报告组命中率、完全命中率、只命中干扰的次数。`soft` 探针单列。淡忘类只在 `gap_variants` 上判定，基准时刻只记录。
- **全局曲线**：记忆条数随对话轮数的增长；`淡忘`与`保留`两类在不同时间间隔下的命中率。

## 回答层打分（草案）

评判模型拿到探针消息、`plants` 中相关的说明、回答，以及 `rubric`，逐条判断：`should` 里的要点是否体现，`should_not` 里的内容是否出现。做两个版本的成对比较时，交换 A/B 顺序各评一次，两次结论一致才计入胜负。

## 写新剧本的约定

- 植入的信息只是顺带说起，从不说“记住这个”。
- 共现关系（例如成像夜与麻辣烫、开会与给妈妈打电话）不能在对话里被任何一方说破，否则这项测试会退化成语义检索。
- “昨天”“上周三”之类时间探针，要配上别的日子里用词相同或相似的干扰。
- 同名、同类事件、否定句都要配上只靠语义就会答错的干扰项。
- 每条探针的金标准不能全部落在探针时刻的 Hot 里（构建会检查）。
- Lumina 的台词按人设写，简短、克制，不替用户总结植入的信息。

## 已知局限

- 规模小：每份 390–550 轮、约 4000–6000 字（dev-a 546 轮、dev-b 424 轮、holdout-c 388 轮），共现统计的信号在前几周本来就弱。
- Lumina 的台词是事先写好的，和真实回答的分布不同。
- 评分要点由人工编写，只覆盖要点，不能证明未列出的内容都正确。
- 探针只在历史的分支上执行，不测“被问过之后记忆变强”的效应。
