## 1. 阶段 0：自动评审

### 1.1 `judge/run_judge.py`

用法：`python judge/run_judge.py --round <轮次目录> --model deepseek-v4-pro --tag deepseek --batch 5`

- 读取 `packet_<set>_<order>.json`，每次调用评 5 条。
- 每次调用的内容：
  - system：`judge/judge_prompt_v1.md`。由你根据 `judge/INSTRUCTIONS.md` 改写成 API 版：打分定义、60 天说明和人设说明逐字保留；去掉“写文件”“不要打开其他文件”这类针对 agent 的话；要求只输出 `{"items":[...]}`。
  - user：完整的 `transcript`，加上这一批条目（JSON）。
- 校验输出：
  - id 与输入一致；
  - `should`、`should_not` 的长度与要点数一致；
  - `alive` 在 1–5 之间；
  - `prefer` 只能是 X、Y 或 tie。
- 不合格就提高 attempt 重试，至多 2 次；仍不合格，这一批记为缺失，并在报告里列出。
- 结果写到 `<轮次目录>/judge_<tag>/out_<set>_<order>.json`，格式与现有的 out 文件相同。
- 评审必须是盲的：评审提示只能包含 packet 的内容。你本人不参与打分。

### 1.2 汇总

`judge/aggregate.py` 增加 `--judge-dir`：默认是轮次目录本身，也就是 Claude 的评审结果；指定时读取并写出该目录下的 out 和 summary。原来的默认行为不能变。

另外修一处：`judge/build_packets.py` 的条目 ID 目前用集合名的最后一个字符做前缀，`dev_a_long8w` 和 `dev_b_long8w` 会撞成同一个前缀。改为用完整集合名做前缀（如 `dev_a-01`），并在 `aggregate.py` 中兼容旧格式；已有轮次不要重建。

### 1.3 校准

在 5 个已有轮次（`v1_B1_vs_P6` 和 4 个 `v2_*`）上运行 DeepSeek 评审，写 `judge/CALIBRATION.md`。每一轮报告：

- **方向一致**：两个评审者的胜方是否相同。
- **条目一致率**：只看两个评审者都给出了一致、非平局结论的条目，偏好相同的比例。
- 两者“说错往事”标记的一致率。
- 活人感分数的 Spearman 相关。

判定标准：至少 4 轮方向一致，且条目一致率 ≥ 70%，DeepSeek 评审就算“可用”。否则算“有偏差”：后续仍然使用它，但所有结论都标注“待复核”，并写明在哪些类别上与 Claude 分歧最大。

本任务后面的所有评审轮次，都用这个脚本加 `aggregate.py --judge-dir` 完成。每一轮都是两个开发集，每集两遍（交换 X/Y 顺序）。

## 2. 阶段 1：“被想起” = 被回答用上

仓库主人已决定：只有回答里真正用上的记忆，才算“被想起”，才得到召回强化和共同召回。

### 2.1 使用检测 `memlab/usage.py`

`used_memories(answer, context_texts, memories, min_overlap=2) -> list[id]`，只用本地计算：

- **内容二元组**：中文相邻两个字组成二元组，去掉含虚字（的、了、是、在、着、过、又、也、都、就、还、不、没、个、这、那、吗、呢、吧、啊）的二元组；拉丁字母取 3 个字母以上的整词。
- `N` = 回答的内容二元组，减去 `context_texts` 的内容二元组。`context_texts` 包括当前消息、Hot 原文和滚动摘要。这样，回答只是复述他刚说的话或近期对话时，不算用上记忆。
- 记忆 m 算“用上”的条件：`|N ∩ 内容二元组(m.text)| ≥ min_overlap`；或者回答里出现了 m 所涉实体的名字（至少 2 个字），且这个名字不在 `context_texts` 里。

### 2.2 回放时由谁的回答来判断

`Config.usage_source` 可取 `surfaced`、`scripted`、`shadow`：

- **`surfaced`**：原行为，进入近联想或远联想就算被想起。
- **`scripted`**：用剧本里紧接着的那一轮林素台词来判断。
- **`shadow`**：主方案。回放时，每写入一轮用户消息，就用 answer_v2、当前召回的记忆块、Hot 和滚动摘要生成一条影子回答，用途为 `shadow`，走缓存，只用来判断用上了哪些记忆，不写进 Hot。
  - 剧本里的林素台词是在没有记忆的情况下写的，会系统性地低估“用上”的次数，所以主方案用影子回答。
  - 滚动摘要照回答模式的方式生成，应命中已有缓存。

召回痕迹同时记录进入上下文的记忆和被用上的记忆。除 `surfaced` 外，Dream 消费痕迹时，召回强化和共同召回都只算被用上的记忆；其余规则（0.5 的权重、6 小时去重）不变。

### 2.3 检测器的验证

从 dev_a 的影子回答里抽 150 对（回答，进入上下文的记忆）：75 对被判为用上，75 对未被判为用上。用 DeepSeek 按固定提示标注，写在 `judge/usage_prompt_v1.md`：“他发来的消息、近期对话、林素的回答、一条记忆：回答是否用到了这条记忆里、而近期对话里没有的内容？只答 yes 或 no。”

- 报告 `min_overlap` 取 1、2、3 时的精确率、召回率和 F1，取 F1 最高的值。只在 dev_a 上选。
- F1 < 0.7 时照样继续，但要在报告中写明。

### 2.4 运行与指标

预设：P6u = P6 + `usage_source=shadow`；P6u10 = P6u + `pi_recall=0.10`。

**记忆层**（两个开发集）：

- 淡忘类在 +60 天的通过率和干扰名次；
- 保留类在 +60 天的完全命中；
- 有组探针合计的 cue 完全命中、@1、@3、MRR；
- 每个探针时刻，未沉睡记忆中 π > 0.9 和 π < 0.1 的比例；
- 召回强化事件总数；
- 同时列出 P6（surfaced）和 P6 + scripted 作为对照。scripted 不调用模型，放在一张表里即可。

**回答层**：P6u 和 P6u10 各跑一次回答运行，`--answer-scope primary`。

**评审轮次：**

- `v3_p1_P6_vs_P6u`，其中 P6 用已有的 `answers_v2/e1_*_P6`；
- `v3_p1_P6u_vs_P6u10`。

**本阶段的目标**：A24+60 不再提起桂花拿铁；淡忘类的 +60 天通过率提高；保留类不下降。

## 4. 阶段 3：共现联想

### 4.1 诊断（先做）

对 6 条远联想探针（A11、A12、A13、B11、B12、B13），用阶段 2 采纳的配置逐条列出：

- 目标记忆有没有写入：记忆 ID 和正文；
- 目标记忆与线索相关记忆之间，事件层各分量的权重（共现、relate、merge、共同召回）；
- 目标记忆在召回分数中的名次，以及它出现在输出的哪一部分；
- 回答有没有用上它：用 §2.1 的检测器判断。

结果写进报告，指出每条失败卡在写入、召回、渲染还是回答。

### 4.2 渲染原因（render_v2）

- 对于输出中不是任何通道起点的记忆（`a⁽⁰⁾ = 0`，只靠扩散到达），找出“起点 i × 层 ℓ”中单步贡献 `a⁽⁰⁾_i · w_ℓ · P⁽ℓ⁾_{ij}` 最大的那一项，把原因写进时间标签后面。
- 按层写法如下，「…」里是 i 正文的前 12 个字：
  - 事件层中权重最大的分量是共现：`常和「…」在同一天`
  - relate：`和「…」有关`
  - merge：`和「…」是同一类事`
  - 时间层：`和「…」在同一段时间`
  - 实体层：`都和{实体名}有关`
  - 语义层：不写原因
- 例：`- （5 月 29 日 周五 下午，约 2 周前；常和「他交了第三批立绘」在同一天）他常点杨枝甘露……`
- CLI 增加 `--render v1|v2`，默认 v1。
- **回答层**：用 render_v2 跑一次回答运行。评审轮次为 `v3_p3_render1_vs_render2`。
- **本阶段的目标**：远联想类胜多负少，且说错往事的比例不升高。
- 诊断显示是召回侧失败时（目标记忆不在前 20），只报告数据，本任务不新增召回机制。

## 5. 阶段 4：长程压测

6 周的剧本里，滚动摘要几乎能装下所有事。本阶段构造更长的变体，检验记忆图在摘要装不下时的价值。

### 5.1 填充对话

`eval_set/fillers/generate.py` 调用 DeepSeek（提示词写在 `eval_set/fillers/filler_prompt_v1.md`），为 dev_a、dev_b 各生成 56 天的填充对话：

- 格式与剧本相同，写入 `eval_set/fillers/<set>_8w.txt`；
- 每周 3–4 次会话，每次 10–24 轮，由他开头、以林素结尾；
- 林素的台词按人设写，简短；
- 话题是新的日常，例如一部剧、做饭、天气、一个新游戏、办事、朋友来访，不能延续任何已有的植入；
- 禁用词：从 `gold/<set>.json` 的 plants 说明和剧本中提取的全部人名、宠物名、关键事物名（例如年糕、陈老师、林晓、小周、阿杰、麻辣烫、成像、knockdown、豆包、老王、小鹿、阿遥、杨枝甘露），整理成清单，一并提交；
- 生成后自动扫描禁用词，命中数必须为 0，否则重新生成该段。

### 5.2 构建

新增 `eval_set/build_long.py`，不修改 `build.py`。构建 `<set>_long8w`：

- 在最早的探针时刻之前、最后一个已结束的会话之后，插入 56 天的填充对话。
- 之后的所有会话和探针整体后移 56 天。56 是 7 的倍数，所以星期不变。
- 金标准轮次的 ID 不变；填充轮次的 ID 以 `f` 开头。
- 重新做与 `build.py` 相同的检查：每条探针的金标准不能全部在 Hot 里；时间类探针的区间必须包含金标准。不满足的探针标为不计分，并在报告中列出。
- 输出到 `built/<set>_long8w.*.json`。

### 5.3 运行

- 在长变体上跑 B1 和最终配置（阶段 1–3 中所有被采纳的改动），先做记忆层 suite，再做回答运行。
- 评审轮次为 `v3_p4_long_B1_vs_final`。
- **额外报告：**
  - 同一配置在短剧本与长变体上的记忆层指标对比；
  - 每条探针时刻，滚动摘要是否还包含该探针关键事实的主要词语。用词面检查即可，列出摘要丢掉了多少。
