# 设计 v5：打通联想，并降低评测成本

2026-09-27。本文是 `DESIGN.md` 的增量设计，只写这一版改什么、为什么这样改，未提到的部分沿用 `DESIGN.md` 和 v4 的最终配置 P6d。执行步骤见 `TASK_v5.md`。

## 1. 背景：联想卡在哪

联想要成立，一件往事得依次经过三步：先被写成“能被想起”的样子，再在合适的时候浮现，最后在回答时被注意到。v3 和 v4 的诊断显示，这三步都断了：

| 环节 | 现状 | 证据 |
| --- | --- | --- |
| 形成 | 从来没有归纳。merge 次数为 0；共现只作为图上的边存在，从没被写成文字，回答模型看不见 | 体重秤（A11）要的是“他遇到读数异常会先核对仪器”，系统里只有培养箱、酶标仪两次独立的经历；“成像那晚吃麻辣烫”只是一条共现边 |
| 浮现 | 远联想位几乎总被连接最多、强度最高的大话题占着；只靠扩散到达的联想拼不过语义起点 | A11 的远联想位给的是“深夜换液”，A12 是愚人节纸条，B12 是“接大单”；B12 的目标杨枝甘露与交稿之间有 .725 的共现边，却排在 20 名以外 |
| 注意到 | 相关的记忆进了上下文，回答也没用上：记忆块是平铺的清单，回答一次生成完，人设又要求克制 | A12 的目标记忆排第 1，回答只是“几点到几点？”；深夜场景下“他常深夜换液”在记忆块里，回答只说“这个点还没睡” |

## 2. 设计原则

- **联想仍然是召回的性质，不是开关。** 三处改动分别落在写入（归纳）、召回（挑选联想位）和回答（回复前先想一下），没有单独的联想模式。
- **规律也是普通记忆。** 它和其他记忆一样会被召回、强化、淡忘和改写，不预设类型；lineage 里的 `kind=pattern` 只用于调试和统计，召回时不区分。
- **规律必须由经历长出来。** 至少要有两个不同逻辑日的实例作依据，由程序检查；模型拿不准时写 none。
- **优先级不变：理解当下 > 创造 > 自发提起。** 这个顺序体现在回答前“想起”的提示里。

## 3. 组件一：Dream 中的归纳（形成）

### 3.1 时机

每次 Dream 在整合操作应用之后、收尾之前执行一次。只有产生了候选组，才调用模型。

### 3.2 候选组

每组至少有一条“本次 Dream 新建或修改过的记忆”，也就是说，只围绕新经历去找同类。三类候选：

| 类型 | 条件 | 组的大小 |
| --- | --- | --- |
| 共现 | 两条记忆在 ≥ 2 个不同逻辑日同时出现，衰减后的 PPMI 分量 ≥ `pattern_cooccur_min`（0.3），且二者不是父子关系 | 2 |
| 前后关系 | 通过 relate 边连通的一组记忆，出现时间跨越 ≥ 2 个逻辑日 | 2–5 |
| 情形相似 | 两条记忆的余弦落在 `[pattern_cos_low, pattern_cos_high]`（bge-m3 下为 [0.45, 0.80]）之间，出现在不同逻辑日，不共享实体，也没有 relate 或父子关系；即话题不同、情形相似 | 2 |

- **去重：** 如果某条规律记忆已经通过 merge 边连到了一组里的全部成员，这组跳过。
- **上限：** 每次 Dream 至多 `pattern_max_groups`（6）组。超出时，按共现、前后关系、情形相似的顺序取，同类内按强度（PPMI、边权或余弦）降序。
- **日期约束：** 每组成员的出现时间合起来，必须覆盖 ≥ 2 个逻辑日。

### 3.3 调用与渲染

提示词为 `prompts/pattern_v1.md`，用途为 `pattern`。

- `{{groups}}` 每组一段，第一行写出牵出这组的线索：

  ```
  组 0（线索：常在同一天出现，共 3 天）
  - m20｜3月11日｜他做实验到深夜时晚饭常随便点外卖，3月11日点了麻辣烫……
  - m40｜4月1日｜4月1日深夜他又抢到成像机时，补拍图四的一个时间点……
  ```

  三类线索的写法分别为：“常在同一天出现，共 N 天”“有前后关系”“情形相似”。

- `{{existing}}` 列出已有的规律记忆（lineage 中 `kind=pattern`），按与各组成员的最大余弦取前 10 条，每行 `mX｜正文`；没有时填“（无）”。

### 3.4 应用

- **`text`：** 新建一条记忆 `m{n}`。
  - 正文取模型给的。
  - `salience` 取模型给的，限制在 1–3。
  - 出现时间和 sources 取各实例的并集。
  - 强化事件：复制各实例写入侧的事件，保留原来的 kind，`ref` 记为 `pattern:<实例ID>`；再在各实例最晚来源时间记一个 1.0 的 `pattern` 事件。
  - lineage 的 kind 记为 `pattern`。
  - 事件层在规律与每个实例之间建一条 `merge` 分量的无向边，权重 1.0，沿用共同抽象的机制。
  - 实例本身不改，salience 也不减半：它们仍是具体经历。
  - 程序复核：并集覆盖的逻辑日不足 2 个时，拒绝这一项并记录。
- **`existing`：** 该 ID 必须是已有的规律记忆。给它补上与本组各成员之间的 merge 边，并按 touch 处理：追加出现时间，记一个 1.0 的事件。
- **`none`：** 什么都不做，只记日志。
- 模型原始响应先持久化再应用，与整合调用相同。解析失败时只跳过归纳这一步，不影响本次 Dream 的其他部分，并记录下来。

### 3.5 为什么这样能打通联想

- 规律写成文字以后，语义通道可以直接召回它：“新秤说我胖了三公斤”与“他遇到测量读数出乎意料时，会先核对仪器”在语义上相近。
- 召回规律之后，还能沿 merge 边把具体实例带出来，一跳就到。
- 共现规律（例如“他成像的那晚常点麻辣烫”）也变成了“今晚又要去抢机时”的语义近邻，不再只靠扩散去碰运气。

## 4. 组件二：按意外程度挑选联想位（浮现）

### 4.1 规则

近联想（k=6）和心上之事（m=4）的选法完全不变。只替换远联想位的挑法：

- **平时的激活 ā：** 对当前快照，让所有未沉睡的记忆节点均匀出发，用同样的转移矩阵 P、λ 和 K 扩散一次，得到每个节点的激活 ā_i。它只反映图的结构。按“快照版本 + 逻辑日”缓存，因为事件边的衰减随日期变化。
- **意外程度：** `lift_i = (a_i + ε) / (ā_i + ε)`。其中 a_i 是这次线索扩散后的激活，ε 取未沉睡记忆 ā 的中位数，作平滑用。
- **候选条件：** 记忆节点，`a⁽⁰⁾_i = 0`（不是任何通道的起点），未沉睡，且未被近联想选中，也不与已选中的记忆近重复；`π_i ≥ assoc_pi_min`（0.2）；`a_i·π_i ≥ assoc_abs_ratio`（0.2）× 近联想最后一条的分数。
- **选择：** 在候选中取 lift 最大的一条，并列时取分数高的，再按 ID。没有候选时联想位空着，不再退回“分数最高”的旧规则。
- **渲染：** 在“顺带想到的”这一条的时间标签后附上原因，只对这一条附。原因沿用 v3 render_v2 的规则：取单步贡献最大的“起点 × 层”；事件层写“常和「…」在同一天”“和「…」有关”“和「…」是同一类事”，时间层写“和「…」在同一段时间”，实体层写“都和{实体名}有关”；只靠语义到达的不写原因。

### 4.2 理由与风险

- **理由：**
  - 大话题连着许多记忆，扩散时从各处收激活，可及度又高，所以旧规则下它们总占着联想位。
  - 按意外程度挑，对应认知心理学的扇形效应：一个概念连着的东西越多，传给每一样的激活就越弱。所以“成像”让人想起的是只和成像连着的麻辣烫，而不是和什么都连着的“赶文章”。这和 PPMI 扣除“本来就常见”的思路一致。
  - 与线索直接相关的大话题，已经由近联想或心上之事覆盖。
- **风险一：平时几乎不被激活的冷门记忆，比值被放大，变成噪声。** 由平滑项 ε、绝对激活下限和 π 下限共同防止；挑不出合格的就宁可空着。
- **风险二：真正需要的联想恰好是只能靠扩散到达的大话题。** 这种情况少见。由 §7.1 的反事实核对量化。

## 5. 组件三：回答前的“想起”（注意到）

### 5.1 提示词

提示词为 `prompts/answer_v4.md`，即 answer_v2 加两处改动：

- 说明“顺带想到的”那一条附有原因；
- 要求先输出一行“想起：……”，再输出一行“回复：……”。“想起”按“理解当下 → 以前类似的情况怎么做 → 偶尔自然地提一句”的顺序考虑，没有就写“无”。

### 5.2 解析

- 取第一个“回复：”之后的全部内容作为回复，去掉首尾空白。
- “想起：”那一行记入 `probes.jsonl` 的 `answer.noticed`。
- 没有“回复：”标记时，用同一请求把 attempt 加 1，重试 1 次。仍然没有，就去掉以“想起：”开头的那一行，其余作为回复，并记录这是回退结果。
- 回复里如果出现“想起：”“回复：”这类残留标记，删掉并记录。

### 5.3 成本

每轮多输出几十个 token。人设不改。

## 6. 组件四：“用上”判断并入整合，并取消影子回答

这一节是降低成本的改动，同时属于记忆机制。

### 6.1 取消影子回答

v4 中影子回答占了 47% 的输入 token。现在改为：

- **实验室里：** “用上”判断所看的“回复”，就是窗口里紧跟在该轮用户消息后面的剧本台词，不再生成影子回答。
- **生产环境里：** 看的是林素的真实回复，接入时无需改动。
- 这会低估实验室里的“用上”次数，因为剧本台词不是在有记忆的情况下写的。但 v4 的强化事件本来就很少，每个集合约 34 次，影响很小。报告中会写明这一点。

### 6.2 并入整合调用

整合提示词改用 `prompts/integrate_v3.md`：integrate_v1 原文不变，只新增“用上”判断一段和 `used` 输出字段。

- 召回痕迹不变：每轮用户消息仍记录进入上下文的记忆 ID，包括近联想、联想位和心上之事。
- `{{recalled}}` 的渲染：
  - 先列出本窗口痕迹中出现过、却不在【被唤起的旧记忆】里的记忆，每行 `mX｜正文`，每条只列一次。已在唤起列表里的记忆不再重复列出正文。
  - 然后对每一轮林素回复写一行：`[<林素回复的轮次ID>] 回复前想起：m12、m5、m30`。
  - 窗口里没有任何痕迹时，填“（无）”。
- **校验：** `used` 中的 turn 必须是本窗口内林素的轮次，ids 必须在该轮之前那条用户消息的痕迹里，不合法的丢弃并记录。`used` 字段缺失时，按空处理并记录。
- **应用：** 被用上的记忆在那一轮用户消息的时间记一次 0.5 的召回强化，6 小时去重规则不变。共同召回只在同一轮都被用上的记忆之间计。
- 这样就不再需要单独的 `usage` 调用。v4 中每次 usage 调用要 2 万到 3.8 万 token，原因之一是记忆正文被重复列出；这里每条只列一次。

## 7. 评测 v3：低成本的评测方式

### 7.1 分层

| 层 | 内容 | 成本 |
| --- | --- | --- |
| 0 | 离线测试 + 记忆层 suite（有缓存时复用） | 不花钱或很少 |
| 0+ | 反事实核对：在 v4 P6d 的本地运行结果（pro 写出的记忆）上，只把联想位换成 §4 的规则，纯本地重算召回，统计联想位在哪些探针上换了人，以及新旧两条是否命中金标准 | 不调用模型 |
| 1 | 定向探针：对与改动相关的少数探针生成回答，并排列出原文 | 很少 |
| 2 | 全量盲评：70 条 | 只用于最终结论 |

### 7.2 盲评材料改为只含证据（judge_prompt_v2）

- **不再附完整对话记录。** 每条只附以下三部分，按时间排序、去重，每条至多 40 轮：
  1. 当时 Hot 的最后 6 轮；
  2. 金标准轮次和干扰轮次，各带前后 2 轮；
  3. 为了能核实回答中关于过去的说法：分别取两个回答的内容二元组，从探针时刻之前的对话里各取重合度最高的 8 轮，各带前后 1 轮。
- **评审规则同步调整：** 回答里的说法只有被这些证据反驳，或者明显无中生有时，才标为说错往事；证据里找不到、也没有矛盾的说法，不算说错。
- **每批 10 条。**
- **两个回答逐字相同的条目**，直接记为平局，不送评。
- **第二遍（交换 X/Y）只评第一遍有偏好的条目。** 第一遍判平局的条目，按“两遍都偏好同一方才算胜”的规则不可能成为一致胜，所以直接记为平局。胜负结果与原协议相同；平局与“不一致”的划分可能不同，报告里要说明。
- 说错率和活人感以第一遍为准。

### 7.3 采纳规则与噪声

沿用 v4 的噪声带 N=7 和 E=2 个百分点，不重新测量。这次评审模型换成了 flash，材料也改成了证据包，这是已知的偏差，报告中要写明。

## 8. 模型

- 所有调用（整合、归纳、摘要、回答、评审、审计、填充）都改用 DeepSeek v4.1 flash。准确的 API 模型名由执行者从 DeepSeek 文档或 models 接口中确认，并写进报告。
- 实验室的模型名改成可配置：`LUMINA_MEMLAB_MODEL` 环境变量或 `--model` 参数。不要再从 `core/model_client.py` 导入 `DEEPSEEK_MODEL`，也不修改 `core/`。
- 缓存键中含有模型名，所以旧的 pro 缓存保留不动，用于追溯 v4。
- 已有结果不重跑：v4 的 P6d 回答、盲评、记忆层指标都直接作为基线。新旧对比中含有模型本身的差异，报告中要写明。

## 9. 参数（`config.py` 新增）

| 参数 | 初值 |
| --- | --- |
| `pattern_enabled` | True（P7） |
| `pattern_cooccur_min` | 0.3 |
| `pattern_cos_low`、`pattern_cos_high` | 0.45、0.80（bge-m3；其他嵌入模型按 `c_sem` 等比例调整） |
| `pattern_max_groups` | 6 |
| `assoc_rule` | `lift`（P7），`score`（旧规则） |
| `assoc_pi_min`、`assoc_abs_ratio` | 0.2、0.2 |
| `answer_prompt` | v4（P7） |
| `integrate_prompt` | v3（P7） |
| `usage_mode` | `integrate`（P7）；可选 `dream_call`（v4 的单独调用）、`lexical`（v3） |
| `usage_reply_source` | `scripted`（P7）；可选 `shadow` |

新预设 **P7** = P6d 加上：归纳、按意外程度挑联想位、answer_v4、integrate_v3（“用上”并入整合）、用剧本台词作回复。

## 10. 已知问题（本版不处理）

- **滚动摘要被截断。** 摘要调用的输出几乎都顶在 1000 token 的上限，末尾最新的内容被截掉；生产端 `core/model_client.py` 也是如此。本版只在报告中统计被截断的比例（输出 token ≥ 990，或以非句末标点结束），不修复。
- **远联想中的“自发提起”** 仍取决于人设。人设是以后单独的模块。
- **评审模型换成 flash 后没有重新校准**，这是仓库主人的决定，结论中要注明。
