# 任务卡 v5.1（/goal）：修通联想的形成环节

**目标：** 一次做完以下四个阶段，中途不要停下来问仓库主人。

1. 零调用诊断、P7 形成基线和候选干跑，定下参数 θ。
2. 按 `docs/DESIGN_v5_1.md` 实现：归纳 v2、规律保护、经由规律的原因、answer_v5、带原话的“用上”，并新建预设 P8。
3. 用 flash 做一次 P8 回放和小规模评测，按设计文档 §7.4 判定。
4. 写报告并提交。

设计细节以 `docs/DESIGN_v5_1.md` 为准。新提示词已提供：`prompts/pattern_v2.md`、`prompts/integrate_v4.md`、`prompts/answer_v5.md`，不要改动。任务卡和设计文档没写清的地方，自己选合理做法，写进报告的“偏差”一节。

## 0. 约束

- **预算：** 累计新增输入不超过 100 万 token，预计约 45 万。超过就停下，写报告说明原因。每个阶段开头打印预计调用次数，结尾打印实际次数，都按用途分列。
- **模型：** 全部用 flash（`deepseek-flash`），走现有的接口。本版不使用 JSON 输出模式。
- **不重跑：** v5 P7 的记忆层结果、规律、回答和盲评，直接作为基线；v4 的结果也一样。保留集不运行。
- **摘要必须命中缓存：**
  - P8 回放时，允许新调用的用途不包括 `summary`（`--new-calls` 中不列出它）。这样一旦摘要未命中缓存，会立即抛出 `CacheMiss`。出现这种情况就停下，报告原因。
  - 开跑之前，先用离线测试确认：P7 的 Dream 请求和滚动摘要请求的缓存键，与 v5 逐字节相同。
- **不修改：**
  - `core/` 和仓库其他目录；
  - `eval_set/scripts/`、`eval_set/gold/`、`eval_set/build.py`；
  - 已有的提示词文件，包括 `judge/judge_prompt_v2.md`。
- **旧预设不变：** 旧预设（包括 P7）的行为和缓存键不变。
- **测试：** 新功能都要有离线测试，原有测试全部保持通过。
- **提交：** 所有改动做本地提交。推送只推 `docs/TASK_v5_1.md`、`docs/DESIGN_v5_1.md`、`docs/RESULTS_v5_1.md` 三个文档，每个阶段完成后推一次。
- `RESULTS_v5_1.md` 必须自成一体，仓库主人和 Claude 只看这份报告。

## 1. 阶段 1：零调用诊断、形成基线与候选干跑（设计文档 §7.1）

本阶段不调用模型。

1. 做诊断 D1 到 D5，结果写进报告。
2. 实现 §7.2 的形成检查，并算出 P7 的形成覆盖数。报告同时给出“文本加来源”和“只看来源”两种覆盖，并写明 §7.4 第 1 条的门槛值。
3. 实现 §3.1 到 §3.3 的候选生成：分句、同一类、三种候选、成员选取、去重、跳过、上限。阶段 2 直接复用这部分代码。
4. 在 v5 P7 两集的全部 Dream 时刻做候选干跑，按 §7.1 的规则选定 θ（`pattern_kind_cos`），写进报告和 `config.py`。

## 2. 阶段 2：实现

1. **归纳 v2（§3.4、§3.5）：**
   - 使用 pattern_v2 提示词，线索和 `{{existing}}` 按 §3.4 渲染；
   - 校验 instances，只按 instances 连边，缺 instances 时拒绝该项；
   - 正文近重复时转为 existing；
   - 任何情况下都不建自环。
2. **integrate_v4（§3.6、§6）：**
   - 规律记忆的正文前标“〔规律〕”；
   - 拒绝针对规律的 revise 和 merge，记为 `pattern_protected`；
   - 核对 `used` 的原话，按三项规则和常用词表执行；记录每条通过项命中的子串，丢弃项按原因分别记录。
3. **经由规律的原因（§4）：** 渲染版本为 render_v4。
4. **answer_v5（§5）：** 按 §5.2 解析，三栏记入 `answer.noticed`，三栏内容不得进入回复。
5. **预设 P8：**
   - 参数见 §8，θ 取阶段 1 选定的值；
   - 新增的请求字段只在启用时进入缓存键。
6. **本地指标脚本（§7.2）：** 覆盖形成、浮现、注意到、回答层淡忘、记忆层（含淡忘失败的逐条归因）和规律卫生。同一套脚本要能用于 v5 P7 的归档和 P8 的运行结果。
7. **盲评：**
   - 每批改为 5 条；
   - “部分第二遍”的汇总照旧。
8. **离线测试至少覆盖：**
   - **分句与日子：**
     - 按 `。；！？` 和 `，` 切分；
     - 删除四种日期写法；
     - 不足 6 个字的段按规则并入相邻段，合并后不足 4 个字的丢弃；
     - 记忆自己的日子不含 merge 继承和规律复制来的出现时间；
   - **同一类与 KD 的计算。**
   - **常在同一天：**
     - 能从合成数据中找出分别写在两条记忆里的共现；
     - 能找出写在同一条记忆里的共现；
     - 同一类的两个分句不成对；
     - 满足 \|C\| ≥ 2 但权重低于 0.3 时不成组；
     - 每条记忆在组里只占一个位置；
     - 至多 8 条记忆、4 个日子。
   - **反复出现：** 日子数下限；成员上限 6 条。
   - **情形相似：** 有 relate 的一对不再被排除；有父子关系、共享实体的仍被排除。
   - **候选范围：**
     - 不生成前后关系候选；
     - 规律记忆从不进组；
     - 只被 relate 的记忆不算“本次触及”。
   - **去重与排序：**
     - 按 §3.3 的顺序执行；
     - 完全相同、子集、Jaccard；
     - 贪心保留的次序；
     - 再次印证的组排后；
     - 每种类型的上限；
     - 最终组号确定。
   - **`{{existing}}`：** 有 merge 边相连的规律排在前面。
   - **pattern_v2 的应用：**
     - text、existing、none 三种结果；
     - instances 不属于本组、少于 2 条、不足 2 个逻辑日、缺失时，各自被拒；
     - 正文近重复时转为 existing；
     - 永不出现自环。
   - **integrate_v4：**
     - “〔规律〕”的渲染；
     - 针对规律的 revise 和 merge 被拒，touch 和 relate 照常应用；
     - 核对原话的三项规则：每种丢弃原因各一个例子；常用词表里的两字词不算命中。
   - **render_v4：**
     - 经由规律到达时，原因写规律正文；
     - 最后一步贡献者是实体节点时，沿用 v5 规则；
     - 其他情况与 render_v3 逐字相同。
   - **answer_v5 的解析：**
     - 正常 json；
     - 字符串里有原始换行；
     - json 前后有杂字；
     - 缺栏；
     - 重试；
     - 回退时三栏内容不进入回复；
     - 残留清理。
   - **本地指标：**
     - 用合成数据验证形成（含“探针时刻之后才写出的记忆不算”）、浮现、注意到；
     - 注意到只看三栏的值，不看键名。
   - **旧预设不变：**
     - P6d、P7 的召回和渲染结果逐字节不变；
     - P7 的 Dream 请求和滚动摘要请求的缓存键，与 v5 逐字节相同。

## 3. 阶段 3：回放与评测

1. **P8 回放（真实调用）：** 在 dev_a、dev_b 上各跑一次，允许新调用的用途为 dream、pattern、answer，不含 summary。产出：

   - 全部规律记忆；

4. **盲评（§7.3）：**

## 4. 阶段 4：报告与提交

新建 `docs/RESULTS_v5_1.md`，必须包含：

1. **执行情况：** 每个阶段做了什么；按用途分列的调用次数和 token 数；摘要是否全部命中缓存；偏离任务卡的地方。
2. **诊断 D1 到 D5：** 逐项写出结果，D1 附 V0、V1、V2 的指标表。
3. **P7 形成基线：** 6 条植入规律逐条写出是否覆盖（两种口径）、由哪条记忆覆盖，以及门槛值。
4. **干跑与 θ：**
   - 每个 θ 下，每次 Dream 平均每种类型的组数；
   - 全部“常在同一天”组的线索和日子；
   - 选定的 θ，以及它是按选择规则的哪一步选出的；
   - 植入规律在干跑中是否出现（仅供参考，A11、B11 单独说明）。
5. **规律：**
   - P8 两集写出的全部规律，逐条列出正文、候选类型、instances（ID 和正文摘要）、覆盖的日子；
   - existing 和 none 的次数，各举几个例子；
   - 被拒绝的项及原因；
   - §7.2 的规律卫生统计。
6. **形成：** 6 条植入规律的覆盖表，P7 对 P8，两种口径都列。注明覆盖它的是哪条记忆，是规律还是普通记忆。
7. **浮现：** 6 条远联想探针，P7 对 P8：目标最高排名、是否进联想位、是否进前 6、联想位的原因文本。
8. **注意到：**
   - 12 条探针的 P8 三栏原文与回复原文，并列出 P7 的“想起”行；
   - 关键词命中表，“想到”和“说出”分开统计；
   - answer_v5 的解析统计：ok、retry、fallback 的次数。
9. **“用上”：**
   - 每个窗口进入上下文的记忆次数、`used` 条目数、通过核对的条数，以及按原因分列的丢弃数；
   - 10 个通过核对的例子，每个列出记忆正文、原话、命中的子串和回复。
10. **记忆层：**
    - P7 对 P8 的淡忘 +60、保留 +60、cue、@1、@3、MRR，两集分列；
    - 淡忘失败的逐条归因。
11. **回答层淡忘：** +60 天回复中提到干扰小事的条数，P7 对 P8。
12. **盲评 J1、J2，每一项都要有：**
    - 汇总表：一致胜、一致负、平、不一致、说错条数与说错率、活人感、符号检验 p；
    - 按类别的胜负表；
    - 全部非平局条目：探针 ID、类别、偏好、一句话理由；
    - 全部被标为“说错往事”的条目及理由。
13. **采纳判定：** §7.4 的四条，逐条写明是否满足，附数字。
14. **成本：** 本任务每种用途的 token 数，与 v5 对照。
15. **最后一节：**
    - 联想三个环节在 P8 中各自的状态，每项附证据；
    - 仍未解决的问题，每条附证据；
    - 下一步建议，只写有证据支持的。

所有改动做本地提交，按 §0 推送三个文档。
