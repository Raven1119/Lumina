## 1. 本阶段交付什么

### 目标与北极星对应

完成一个可运行的最小闭环：**同一个 Mind 持续承担一项追求，依据事件主动取证、修订理解，并选择当前工作；Nervous 可靠决定何时送来什么信息；Execution 在正确的任务与授权版本下实施。**

北极星要求连续整体心智、独立判断、主动探索和从经历中改变自身。[L1] 本阶段只验证其中三个功能：

1. **持续承担**：同一 Intention 跨两个不同的有界任务、暂停和重启延续；任务完成不自动终结追求。
2. **选择性关注**：相关变化能引起重评，无关信息不使目标漂移；被暂缓的信息可回查、可恢复，不能丢弃或合并成另一条事实。
3. **有限自主性**：Mind 可在已有授权内修改自己的追求与关注条件；没有当前 Task 或 Intention 时，也能进行一次获准的探索／反思，形成候选追求或保持无追求。

这里的注意力指模型输入选材和认知活动调度，不是操纵模型内部 attention 权重。行为上的持续追求不等于已经证明主观体验、人格或通用自主性。

### 范围冻结

**本轮实现**：小型 Intention 状态、一个当前焦点、串行 Task 承接；现有 trigger 集中注册；来源变化 Watch、一次性到期重评；Nervous 的有界上下文选择；Mind 的执行状态／历史主动查询；对应的恢复与验证。

**本轮不实现**：UI、Chat 接线、Memory/Dream/Evolution、人格或欲望计算、多目标竞争调度、后台常驻服务、周期性完整思考、通用插件市场、模型切换、新数据库。未来影响入口只留一个有来源的可选字段，不建空壳系统。

只支持前台安全边界推进。到期与外部变化在进程运行或 `resume` 时检查；进程退出期间不会自主感知。测试使用可注入时钟，不用等待现实中的几天。

允许少量候选／暂缓记录，但一次只有一个主要焦点、一个执行中的 Task。核心验收是 A 收尾后承接 B；不同时实现“挂起多个任务并相互抢占”。

## 2. 实现契约

### 2.1 唯一所有者与状态

| 状态 | 唯一所有者 | 核心内容 |
| --- | --- | --- |
| Intention 与认知 | Mind | 追求、认同理由、承诺状态、相关 belief/question、修改依据 |
| 注意与 trigger 状态 | Nervous | Focus 引用、Watch、待处理／暂缓信号、调度位置、已准备输入的引用 |
| Task 的提出与目标修订 | Mind；授权来自真实 owner 输入 | 有界目标、验收条件、Intention 关联、授权引用 |
| Task 接纳、Run 与行动事实 | Execution | 已接受任务版本、Run、动作、结果、等待和恢复状态 |

Task 是跨器官传递的不可变版本契约，不新增 TaskManager。Mind 保存自己提出的版本和判断，Execution 保存接纳回执及实施事实；两者通过身份关联，不共同覆盖一份进度字段。

Intention 最小记录可采用以下形状；字段名由实现者决定：

```yaml
id: intention-001
revision: 1
aim: 让自己的研究判断能够经得起独立核查
why: 已有经历暴露出交付成功与证据解释正确之间的差距
commitment: committed  # candidate / committed / paused / closed
origin_refs: [event-017]
understanding_refs: [belief-012, question-006]
influence_refs: []    # 未来动机来源，本轮不生成模拟人格或欲望
```

状态转换必须有理由和基础版本。进展含义由 Mind 依据结果评估，实际动作状态来自 Execution。没有可信量纲时不生成完成百分比。长期追求可以是达到、维持或培养某状态，不强制都有终点。

权威记录扩展现有 Cognition 提交／重建机制，存放在持久 Mind 私有目录，不能放入某个 Run 或业务工作区；Markdown 是可选只读导出。Focus 不等于 Intention：退出上下文不退休承诺，暂停投入不抹除未决问题，摘要不能修改其状态。

未来欲望／人格只需经相同只读视图提供 `来源、版本、内容、适用范围`，由 `influence_refs` 引用。没有真实来源就为空；动机不能充当现实证据、任务授权或预算。

### 2.2 自修改与跨 Task 连续性

Mind 在正常 `cognitive_step` 中可选提交 Intention 更新、关注请求和下一项 Task；无变化不重写，允许只修订理解后 NoChange。语义校验仍由模型承担，程序检查类型、引用、版本、边界和授权。

```text
事件／主动查询结果
→ Mind 判断影响的是方法、Task 还是追求
→ 同一次认知提交保存变化与待发效果
→ Nervous 应用 Watch／Focus 更新并传递任务或指导
→ Execution 幂等接纳／拒绝，反馈到同一 Mind
```

**自主性授权**：Mind 可在当前获准的研究范围内形成候选、承担、修订、暂缓或结束自己的追求，也可提出后续有界 Task。改变用户明确交付、扩大工作区／工具权限或增加预算，不能仅由模型自述授权。本轮实验的初始真实输入明确允许在给定材料、工作区与总预算内选择后续工作，避免每个内部选择都要求再次确认。

**跨任务**：保持 Mind 身份和 Intention 身份；A 与 B 使用不同 Task ID，各自拥有明确 goal、验收和授权。A 的 Run 与完成标记只证明 A 的对应状态，不满足 B。新 Task 不通过向原 goal 字符串不断追加指令实现。

**当前任务修订**：已派发契约不原地覆盖。影响 A 的新要求必须成为可核对的 Task 版本，在已知安全边界承接；未执行旧计划按适用性退休，已完成动作保留，未知结果仍阻断。首版不在 A 未结清时偷偷启动另一个执行中的 B。

**变更传播**：普通 Intention 文案变化不机械重启 Task。Mind 明确指出本次是否影响当前任务／关注条件；结束追求时，关联 Watch 不再继续自动触发，仍在执行的任务需要显式处理。订阅更新尚未确认时，相关派工不得越过必要的版本同步边界；不要为此创建跨器官全局事务管理器。

解除单 Task 绑定时同时检查 `task_view`、Analysis 的 owner_task、证据引用和工作摘要 scope。旧活动及已保存请求仍按原身份解释；进入 B 时不得自动注入 A 的完整证据、用户消息或全量背景。相关历史可以按需读取。不得为了让 B 能启动而创建全新 Mind、清空认知或重置累计资源。

### 2.3 TriggerSpec 与 Watch

**TriggerSpec 是受信代码；Watch 是 Mind 提交的数据。** 前者定义信号模式、判据、投递方式和上下文配方；后者指定关注的对象、Intention、条件或到期时间。运行时不执行模型生成的 Python、DSL 或自然语言谓词。

建议只增加 `Nervous/triggers.py` 与 `Nervous/attention.py` 的职责；可依现有结构合并，不限制文件数量。静态注册表即可，不建插件加载器。

```text
TriggerSpec: id + version + 可信来源/事件schema + predicate
             + delivery_mode + context_recipe
Watch:       id + revision + spec_id/version + 参数 + owner引用 + 状态
```

先将现有行为迁入注册表，再仅新增两种 Watch：`source.changed` 与 `review.due`。名称为示意，已有事件名及明确语义优先复用。

| trigger／信号 | 调度行为 | 本次上下文重点 |
| --- | --- | --- |
| 显式停止、撤权、未知动作／完整性故障 | 先机械关闭相关新动作接纳；不等待 Mind 同意 | 受影响 Task、控制来源、已知／未知结果、当前边界 |
| 用户新输入 | 安全边界进入同一 Mind；独立提交身份 | 原始输入、当前追求／Task；无关联时提供可分页目录 |
| evidence／analysis／view 查询结果 | 续接原活动，优先解除其等待 | 原 request、结果、来源版本和缺失状态；不启动第二次独立判断 |
| Execution 请求判断、重要等待／失败／完成 | 相关活动，普通工具轮次不逐一送审 | 精确问题／结果、当前 Task、相关指导及必要历史片段 |
| `source.changed`，含已有预测观察 watch | 来源的新观察版本变化触发；不判定语义真伪 | 新旧来源、观察时间、关联条件／假设；普通来源变化不强制有世界模型 |
| `review.due` | 一次性到期机会；忙时延后，恢复后不补发重复机会 | 注册理由、计划与实际时间、相关关切、资源和外围信息目录 |
| 普通 ack、状态查询、摘要保存、常规工具日志 | 不新增认知活动 | 保留在原 owner；按需查询 |

外部文件变化仍由 Execution／环境适配器观察，Nervous 按版本信号选择触发。不要把业务文件扫描、世界模型计算或认知判断搬进 Nervous。已有预测的注册基线、通知已处理与比较已完成之区别全部保留。

`review.due` 可由 owner 或 Mind 安排；允许没有当前 Task 或 Intention，并可用于一次有界探索。该活动可以提出候选追求，也可以 NoChange。取消、消费与重新安排有独立身份；普通 `resume`、重启或刚保存 summary 不会产生新的到期机会。首版不建立自动周期 heartbeat，也不要求“每次空闲都找事做”。

时间由可注入时钟提供，持久化绝对到期时间和机会身份。前台检查时才产生到期信号；记录迟到时间，不伪造准时执行。来源变化只承诺捕获实际观察到的变化，不宣称发现进程离线期间未观察的 A→B→A。

未知的 signal 类型保留为未路由／拒绝记录，不凭字符串自动绑定权限。Mind 可扩大查询与关注范围到授权内未关联信息；固定配方不能成为只能看当前 Task 的永久边界。[R2,R3]

### 2.4 Nervous 的上下文构建与主动查询

各 owner 提供**有界、版本化、只读视图**。Nervous 负责跨来源选择与调度；Mind 继续拥有认知内容、提交语义和 provider 消息序列。不要在两个模块中各保留一份不同的选材策略，也不要让 Nervous 读取器官私有文件或调用其语义推理。

```text
AttentionFrame = fixed_policy(
  已接纳trigger, 各owner的版本化视图, 注意状态, 本轮预算
)
```

同一组输入和策略版本必须产生同一选材清单。时间、状态版本等外部量先作为输入冻结；整个模型请求仍由原 provider 适配器构造并记录。

| 层级 | 选材规则 |
| --- | --- |
| 必要核心 | 本次事件／原文引用、有效授权、当前焦点及相关 Intention、当前 Task、关键阻断、能力和剩余资源 |
| 直接关联 | 按 task/intention/request/source 身份获取相关判断、变化前后证据及最小轨迹区间；来源不存在或未读需明确标记 |
| 外围与按需展开 | 暂缓事项及未关联新信息的短目录；稳定顺序、分页和取回引用；Mind 可主动选择展开，不只提供支持原观点的材料 |

首版不引入向量排序、学习型注意力或新摘要器。排序与容量参数集中配置，记录为何选入／省略，不按“最先遍历到的短文件”冒充相关性。所有当前有效的权限和 Task 约束保持可见。

每份 view 带 `owner、ref、revision/as_of、scope、content或引用、缺失/截断状态`。不同 owner 的快照只能报告各自采样点，不能伪称全局原子现实快照。大正文通过有界引用展开。

**Mind 可见内容**：实际进展与验收证据目录、相关认知与未知、剩余预算／上下文空间／可用能力、Execution 当前状态与重要结果、相关外界变化，以及其他关切的短目录。资源状态不拟化为情绪；动作数不拟化为进度。Execution 仍只看到当前 Task 和必要长期背景，不获得全部 Mind 历史。

**主动查询**：复用 `read_evidence`，增加一个小的已注册 view 查询入口，覆盖执行状态／有界执行历史，以及 Nervous 自身资源与待处理目录。可查 Intention 由 Mind 的只读视图提供；不新增通用查询语言。

```text
推送：信号 → 持久接纳 → trigger判据 → 安排/暂缓 → 取视图 → 冻结Frame → Mind
查询：Mind → request(activity_id, request_id, view, 范围)
     → Nervous路由 → owner返回view → 原活动追加delta → Mind继续
```

读取已保存状态与请求新的环境观察需要显式区分。`status` 永远不采集新观察或产生调用。查询失败返回真实失败／容量信息，不转成“没有证据所以事实不存在”。仅输出获准的行动／结果投影，不把 provider 私有正文、凭据或完整内部推理作为公共轨迹视图。

已有 summary/mask/baseline 继续保留原含义和默认设置。Nervous 选材可以消费已有派生背景，但不能把摘要 ref 变成事实依据。历史输出被原工具截断的部分不能由新查询恢复。

### 2.5 进入、退出与恢复注意

**同一活动内**：Frame 与原生请求基线保持不变，查询结果只按原 request 追加；不每轮重新选一个 Intention。真正影响任务授权的信号先阻止不适用动作；本阶段在活动安全边界进行新的重评，不热改在途 prompt。

**活动之间**：按当前版本重建 Frame。退出注意不执行 cognition 的 `current` 退休语义。未选中的认知仍保留；修改不在当前可见集合的条目，应先读取其当前版本。工具 schema 的 ID 枚举、目录和补充说明同样计入最终请求预算，不能通过这些侧路再次塞入全库。

**暂停与返回**：Nervous 仅保存焦点引用、未决事项、返回原因和 owner 检查点引用；实际 checkpoint 属于原器官。恢复时先认领已知结果，再决定是否构建新活动；不能将新 Frame 绑定旧响应。

待处理控制、原活动 continuation、一般新唤醒分别处理。continuation 优先解除当前活动等待；普通新事件在忙时暂缓，不合并、不丢弃。相同层级选择最早就绪项；由于本轮只在活动边界换焦点，不允许新的普通工作无限插队。队列饱和时明确背压并保留已有责任，不能静默清空。

跨活动旧状态以历史标记呈现，当前 Intention 只使用当前有效版本。外部文本和动机是数据，不能注册 trigger 或覆盖系统指令。新版本改变旧来源适用性时，在新活动或执行派发前验证；保留过去判断发生过的事实。

### 2.6 三个提交边界

| 边界 | 持久性要求 |
| --- | --- |
| 原信号 → 待关注责任 | 收到、已排入注意和已处理不是同一 ack。原信号仍未确认，或待关注责任已同次原子接纳；不得先 ack 再保存待办责任 |
| Mind 提交 → Watch/Task 生效 | 复用提交日志、outbox 和幂等 handler。保存效果的身份与基础版本，崩溃后继续应用；不依赖跨文件“同时成功”的假设 |
| 准备Frame／查询 → 模型调用 | 保存来源版本与实际输入；已有响应不重采样，未知调用保持停止。重复投递不重复创建活动或收取一次新调用 |

优先扩展 Nervous 已有存储事务边界，不另加一套相互覆盖的调度数据库。暂缓记录可以保留原事件为 pending；若为避免队头阻塞转移责任，新的持久责任必须先成立。[L3]

每个真实变化有 occurrence 身份；同一 occurrence 命中多个规则记录多个原因，不制造重复判断，不把独立 occurrence 合并。A→B→A 的后一个 A 是新观察；同一待处理通知的重传仍是原身份。只按内容 hash 或进程启动时间生成身份均不合格。

Watch 结束／更新后，旧信号仍保留历史，但派发前检查其适用性，不激活已经结束的追求。新增信号留在当前 Frame 之外等待处理，不因本次落盘而提前消费。

## 3. 实施、验收与交付

### 三个切片，依次完成

| 切片 | 交付 | 先证明什么 |
| --- | --- | --- |
| A：现有信号与选材归位 | 小型注册表、AttentionFrame、现有事件的配方和可靠暂缓 | 对旧单任务场景，触发时机、判断次数、来源与恢复语义不退化；结构迁移本身不宣称行为收益 |
| B：持续追求承接两个任务 | Intention 状态与自修改、Task 身份分离、串行任务切换 | 同一 Mind 未重建，A/B 有不同目标与验收；旧结果不混入新任务权威，预算不重置 |
| C：主动关注闭环 | source.changed、一次性 review.due、状态／轨迹查询；无Task/Intention的一次有界重评 | 能主动取证、返回原关注或提出候选；未命中、无任务和静默恢复不制造无限调用 |

每片先测试后实现／晋升，全部完成后停止。允许 Astra 改变内部文件安排或选择更简单等效实现；这里冻结的是行为与 owner 边界，不是类图。

### 验证必须区分机制与判断质量

| 组别 | 最小覆盖 |
| --- | --- |
| 连续性与自主性 | 相关经历使 Task B 的选择发生合理变化；无关消息不改承诺；充分反证允许改向；空白追求状态的一次重评允许 candidate 或 NoChange |
| 信息与注意 | 推送命中所需视图；查询返回原活动；未关联信息可展开；短目录和证据类型保留；离开/返回不丢未决问题，旧Task/旧版本不冒充当前 |
| 故障与静默 | 事件接纳、Frame保存、认知提交、Watch应用、查询结果回流处的定点崩溃；A→B→A；到期延后/取消/重启；未知动作不重放；普通日志不唤醒；无新工作恢复新增调用为零 |

确定性测试应断言具体 identity、版本、输入片段、调用次数和文件结果，不能只断言状态为 PASS。小型测试插件注册一种新 trigger，证明不用改中央 `if/elif` 即可接入；不因此建设正式插件生态。

每片运行受影响回归；收尾运行 `python -m pytest Mind Nervous Execution -q` 和维护套件 `python -m pytest -q`。在用户 Windows 工作区使用已准备的 `.venv/Scripts/python.exe`，测试状态放到仓库外临时目录。Docker opt-in 与真实模型验证分别报告，不混入默认套件计数。

真实验证只做小样本：在授权隔离工作区，以一项具体研究追求推进两个串行任务；B 必须由当时证据选择，不能把 A/B 清单硬编码进生产策略。追加一个相关反证和一个无关干扰，检查判断、工作选择和产物。再做一次无当前任务的有界重评。模型、thinking 和工作上下文模式保持冻结，只改变本片机制。

本轮真实调用上限为 **32 次**，经现有账本统一计入 Mind、Execution、Analysis、摘要、修复及失败请求；运行前冻结并记录总输出与请求体预算。用现有 `deepseek-v4-pro` 官方入口和环境加载，不迁移模型。到限就保留不充分结论，不为跑出成功继续加预算。没有有效凭据或 Docker 时完成不受影响的实现与离线验证，准确列出未运行项。

验收看实际选择与动作，不看 `why` 是否动人。通过这些样本只能说明受界机制与对应行为；没有对照优势不得声称“更像人”或“自主性普遍更强”。失败后保留原始调用在本地恢复目录，仓库仅提交必要回归与凝练结论，不再次堆积实验 harness。

### 兼容、资源与安全范围

既有 CLI 和 manual Execution API 不被静默接入新模式。为持续追求／一次性重评增加最小明确入口，参数命名由实现者选择；旧 `--goal` 的语义不偷偷变成长期人生目标。允许为本阶段新契约使用新状态目录，旧状态不得自动清空、猜配或重新解释。无需恢复已经退休的历史实验协议。

保留当前恢复与工作上下文机制；模型输入不足时可恢复地停止，不能裁掉授权、未知动作或关键事件后继续。每个 Task 换代不重置 Mind/Nervous lifetime 或累计费用；本轮不开发无限期归档。只有新协议开销确实撞到现有上限时，才凭测试调整相关显式上限，并记录理由，不能整体解除边界。

核对已修复的状态诊断漏项，若本地已经修好，仅跑相关回归。不要借本轮重做恢复基础设施。

### 文档与结束条件

更新 `docs/CURRENT_STATUS.md`、`Mind/docs/INTEGRATED_CHAIN.md`、实际受影响的 Mind/Nervous 架构说明和必要的 AGENTS 链接。明确本轮授权 Nervous 做确定性输入选择，旧文档的“只传输”描述相应细化；Mind 仍拥有语义和认知提交。上一阶段设计作为历史设计保留，不篡改其原验证结论；对不再适用的范围说明添加本阶段引用。
