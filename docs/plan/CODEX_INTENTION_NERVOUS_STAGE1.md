# Codex Astra 任务卡：Intention × Nervous 阶段一

## 1. 目标与授权

阅读 `AGENTS.md`、相关局部指引、`docs/NORTH_STAR.md`、`docs/CURRENT_STATUS.md` 和 `docs/plan/INTENTION_NERVOUS_STAGE1.md`，核对实际 HEAD、工作树与当前入口，然后完成阶段设计的实现、验证和文档交付。

本轮明确授权：在现有持久化基础上，增加长期 Intention 的自主修订、同一 Mind 对串行 Task 的承接，以及 Nervous 的 trigger 注册、确定性上下文选择和主动查询路由。让持续追求实际影响关注与行动，不只增加目标字段或待办列表。

使用适用的 codebase-design、TDD、code-review 等 skills。普通可逆选择自行决定；允许根据源码和北极星推断合理实现，并以更简单的等效方案替换文档示例。不要停在计划阶段，不为非关键命名或文件布局反复询问。

## 2. 按三个切片推进

1. 将现有 trigger 与跨来源上下文选材归入 Nervous 的小型注册／配方机制，先验证旧行为不退化。
2. 实现版本化 Intention 与当前 Task 分离；同一 Mind 跨两个不同 Task 保持追求，并可因证据修订、暂缓或结束。修改承诺不增加外部权限。
3. 接通来源变化、一次性到期重评及状态／执行历史查询；允许无当前 Task/Intention 的一次获准思考。信号推送启动活动，查询结果续接原活动；暂缓事件不合并、不丢弃。

复用现有 owner、事件事务、outbox、调用账本和工作上下文。Nervous 负责何时送什么，Mind 负责意义和追求，Execution 负责行动。先保存再切换；已知响应与动作不重复，未知副作用继续阻断。新旧任务、来源和关注条件的版本必须可核对。

不做 UI、Chat/Memory 接入、欲望/人格计算、后台守护、多任务竞争、Evolution、模型或数据库迁移。摘要保持现有默认。保护用户数据及未提交修复；未经另外授权不 commit、push、reset 或重写历史。

## 3. 验收与交付

先做故障注入、错误／过期信号、主动查询、A→B→A、静默恢复和跨任务污染回归，再做设计文档限定的小型真实验证。沿用官方 `deepseek-v4-pro`，所有角色、修复和失败合计最多 32 次真实请求，运行前冻结其他资源预算；不得自动追加。缺少环境时继续其余实现，明确未验证项。

证明同一 Mind 的追求跨 Task 延续，B 根据实际证据选择；相关变化促成取证或改向，无关变化不诱发漂移；候选追求可产生也可不产生；恢复无重复副作用。测试通过不等于拟人效果成立。

更新 CURRENT_STATUS、运行契约、受影响架构说明及必要 AGENTS 链接。报告实际变更、复用来源、验证结果、成本与限制；保留失败，本地保存原始实验记录，公开树只留必要回归与结论。完成本阶段后停止。
