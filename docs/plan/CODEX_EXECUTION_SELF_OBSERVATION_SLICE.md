## 2. 实现一个最小、可关闭的自观测切片

先从保存的失败轨迹定位连续重复检查，核对动作、结果、环境版本和当时真正进入模型的上下文；报告中的“顺序调整后仍失败”“开发者反馈后才退出”“Mind 输出 NoChange”均是事实边界，不预先认定缺少 Mind 指导。

由 Execution 基于已提交、结果已知的动作记录，生成有界重复证据。首版仅覆盖同一 Task/Run 内连续相同动作、相同已观察结果，且相关已观察来源未变化的情形；一次冻结阈值，可先用三次完整重复。记录动作/结果引用、次数、来源版本、当前运行及复核状态，不把整个私有日志加入上下文。

字段名与实现布局自行决定，优先复用 `Execution/runtime.py`、现有历史投影、`Nervous/triggers.py`、attention/query、outbox 和 receipt。称其为“重复已观察到”而非确定的“无进展”：未见文件变化不证明没有内存进展，重复次数不能成为业务失败或完成证明。首版允许漏掉交替循环与语义等价代码，不做复杂归一化。

Nervous 的小型确定性规则接收证据，按模式仅投影给 Execution，或再触发同一 Mind 的有界重评。不要伪装为用户消息，不增加语义裁判。Mind 可查询相关历史、NoChange 或提供高层方向；代码不代选工具、不自动 ClaimComplete、不修改 Intention 或补写业务报告。若 Mind 选择 NoChange，Execution 仍能看到同一份真实重复证据，不能把希望寄托于一句未传递的新指导。

同一未变化重复片段只通知一次，跨轮询和重启不反复触发；通知、查询结果和 NoChange 本身不重新武装。新的实际观察、任务边界或明确关注变化可以开始新片段。来源身份与发生序列分开，不能把后来的 A→B→A 当作旧重试。保留已知响应复用、未知动作阻断、STOP/REVOKE 和原生工具配对。原完成声明可安全续接时先用现有完成机制，不再额外制造重评。

## 3. 验证与交付

先做确定性回归：重复证据的生成/路由/持久化、已通知后崩溃恢复、NoChange 不造成唤醒循环；反例覆盖相同动作但新结果、不同观察范围、未结束的长计算、真实 WAIT、不同 Task 以及已完成后的安静恢复。仅原文结果被截断时不能声称完整结果相同。至少使用一个不含原报告词句的新场景，避免针对“信号/请求”等词打补丁。

随后冻结同一任务、材料、安全前缀、模型配置和等额总调用预算，依次比较：

| 模式 | 唯一差异 |
| --- | --- |
| A | 当前 baseline，不提供新重复通知 |
| B | 自动生成重复证据，只给 Execution |
| C | Execution 收到与 B 相同的证据，同时经 Nervous 交给 Mind 重评 |

分别记录检测时点、实际证据是否送达、Mind 是否读取/干预、后续重复次数、正确续行/合法完成、总调用及 tokens。A→B 检验新增自观测，B→C 检验跨器官复核增益，不能仅凭 C 成功宣布 Mind 有优势。三组只是诊断性小样本；若 baseline 没有复现问题，记录 INCONCLUSIVE，不反复改样本或挑成功轨迹。真实比较期间不得由开发者注入停滞提示、结论或下一步命令。

本卡限定新实验最多 24 次真实请求，每组最多 8 次，所有角色、失败、修复、摘要均计入；全局新增预留输出最多 393216 tokens，请求体最多 5760000 bytes。沿用官方 `deepseek-v4-pro` 及原 thinking 设置。运行前登记，不能自动追加或沿用旧任务的扩额权限。额度不足或环境不具备时保留现场并报告，不伪造完整验收。

依据证据决定采用 B、C 或均不晋升；功能暂保持 opt-in。不得为了证明架构价值强行保留效果更差的路径。运行受影响测试、核心/维护套件及相关 Docker 检查；明确哪些是真实模型、脚本响应、函数级测试或未运行。

交付一个短结果文档 `Mind/docs/REPETITION_REASSESSMENT_RESULT.md`，更新 CURRENT_STATUS 和必要运行说明。保留阶段一原 verdict，记录此次变更、选材和路由、对照结果、成本与剩余限制；原始实验资料仅留私有测试存储。完成这个切片后停止。
