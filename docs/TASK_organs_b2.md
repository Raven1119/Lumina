从 `organs` 干净快照开始；保留旧分支私有文件，查实际数据路径并完整备份。记录全树、`tests/`、`Execution/` 与实验室离线测试基线。读取 B 阶段 R1 第三次原始响应，解释零派活零回复。逐条列出八次主动说话的 Mind 原文与最终文本，并判断 R2 重复追问在哪一边。只有 Mind 原话不能直接发、Language 修好且意思不变，才保留主动重组；否则新增并默认 `language.render=never`。

## 阶段 1：Mind 原生工具

实现前最多四次真实调用验证：对话关闭 thinking 可同时返回文字和工具；非对话 low thinking 的多步工具回传可用。对话关闭 thinking，非对话开 low thinking；后者必须按供应商文档回传 reasoning content。复用 Execution 已验证的 OpenAI 兼容请求构造、工具调用解析和供应商错误处理，不能复制整份实现。A1 完全不改。

每步都提供六个工具，调用后带结果继续，没有调用则结束。回复/说在哪步出现就在哪步发出；与本思考已发文本完全相同的不重复发。最后一步设置 `tool_choice=none`；供应商仍返回工具时不执行，计数并在思绪加中断注。思绪/带着只取最后一步。文字 `行动` 忽略并计“协议残留”。每步最多 `mind.tool_max_calls_per_step=8` 次，超量调用返回错误。完整模型响应（含工具 ID 和必要 reasoning）先落盘，工具结果按思考/步骤/序号落盘，重启不得重复执行；派活 ID 由幂等键导出。

工具名、必填参数与成功结果：

| 工具 | 参数 | 成功结果 |
| --- | --- | --- |
| `read_file` | `path`：工作区相对路径 | 文件文本；超过上限截断并注明 |
| `recall` | `clue`：一句线索 | 带编号回忆，空为“（没有想起相关的事）” |
| `delegate` | `goal`, `reason`, `acceptance`, `context` | 已派出帮手编号及 `tasks/<编号>/` 目录 |
| `answer_helper` | `helper`, `content` | 已答复帮手 |
| `cancel_helper` | `helper` | 已让帮手停下 |
| `hold_question` | `helper` | 已让帮手先等着 |

每个工具的中文说明和精确错误文字由 `Mind/tools.py` 的 `MIND_TOOLS` 与结果分支固定：缺参数或空值、帮手不存在/已结束、不在提问、未知工具、非法 JSON、本步超限都必须以工具结果返回模型，不静默丢弃。`delegate` 内部映射 `goal/reason/acceptance/context` 到现有中文任务契约。对话提示全文落在 `prompts/dialogue_a2_persona.md`，非对话提示全文落在 `prompts/mind_event.md`；后者 system 为完整 `chat_background.md` 加提示，不再引用“同对话时”。无工具返回时继续使用 answer_v5 的文字协议。非对话文字解析失败时，关闭 thinking、无预填重试一次；仍失败不说话，提问自动答复。

确定性测试覆盖工具格式和结果回传、派活及一次回复、参数和帮手错误、末步禁工具、协议残留、坏引号救援、响应/工具两个崩溃点、thinking 回传、解析重试，以及 A1 字节比较。

## 阶段 2：上下文、结果和稳定性

非对话思考最近六轮对话合成单条 user“最近的对话”块，放在状态块前；帮手消息包含目标、理由、验收、背景、期间按时间列出的提问与答复（含“她答的”或“自动答复”）、它的说明与产出。若答案已经在对话或问答里，应直接答复，不再次问他。具体呈现格式由 `Mind/runner.py` 实现并以确定性测试固定。

帮手提示全文放在 `prompts/helper.md`。正常结束前先写 `.lumina-outcome`：首行 `完成`、`部分完成` 或 `做不到`，随后简短说明；再写 `.lumina-complete` 为 `done` 并 `ClaimComplete`。完成标记只表明结束。缺失或无效的自报记 `未说明`。终态为“已交回 / 失败 / 被拉闸 / 已取消”；回报带自报结果和说明，产出不列两种标记。终态与回报事件同一 SQLite 事务，启动时按固定事件 ID 补发缺失回报且不重复。

`/api/chat` 响应类型：`model` 为说的话；`none` 是无话、空文本；`error` 是调用/事件失败的简短原因；`pending` 是首答超时、空文本，后续历史刷新显示。后三者不写 Hot 或记忆。前端隐藏 `none`、灰色系统提示 `error`、`pending` 保持思考中并轮询。model 模式不出现旧占位句。

调度器逐事件隔离异常，`nervous.event_max_attempts=3` 后确认并写只含事件编号、类型、异常类型、时间的死信；用户消息死信得到 `error`，工作线程继续。`/api/status` 给出死信数量。Mind 事件与帮手池事件互不阻塞。按阶段 0 诊断落实 `language.render` 默认值，并保留其它取值。
