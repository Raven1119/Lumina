# 任务卡（/goal）：器官重构 B2 补丁 —— 说到做到，处理过时提问，接通默认工作区

## 目标

开始真实试用前，修掉 B2 情景验收暴露的问题：

- **说到做到：** 她口头说"我去安排""我让帮手试一下"，就必须在同一次思考里真的派出帮手（B2 的 R3 第 1 次没有做到）；
- **过时提问：** 帮手已经结束后，它没处理的提问不再叫醒 Mind（B2 的 R5、R6 中，她去答复已结束的帮手）；
- **重复提问：** 查清帮手为什么把同一个问题问两遍（B2 的 R2 两次都出现），原因明确就修掉；
- **默认工作区：** 在仓库主人接通 Docker 之后，用仓库默认的 `workspace/` 跑一次真实情景。

一次做完，中途不要停下来问仓库主人。开始前，仓库主人已按 B2 讨论里的步骤，在 Docker Desktop 中打开了 WSL 集成。

## 本卡不做

- 主动说话的长度和风格（见决定第 5 条）；
- 其他种类的触发器、人格系统、冥想、进化；
- 改动 Execution V2（`Execution/execution.py`、`organ.py` 等）、记忆算法、Dream、Cold 数据、`answer_v5.md`；
- 盲评。

- 如果诊断发现，修重复提问必须改 Execution V2，就**不修**，只在报告里写明原因和建议的改法。

## 决定

仓库主人如有不同意见，只需改本节对应的一行。

1. **说到做到（只改提示词）：**&#x20;
   - 对话提示、非对话提示、帮手提示分别按附录 A、B、C 修改，只改附录指明的位置；
   - 不做任何"从回复文字里检测承诺"的代码判断。
2. **过时提问：**&#x20;
   - Mind 处理一批帮手提问之前，先剔除过时的：帮手已经结束（终态），或者这个问题已不再待处理（已答复、已取消）；
   - 剔除的事件直接确认掉，写一条记录，内容包括事件编号、帮手编号和原因，不含问题原文；同时计入试用统计的"过时提问"计数；
   - 一批提问全被剔除时，不启动这次思考，也不自动答复；
   - 帮手结束时如果还有没被答复的提问，把这条问答标成"没等答复就结束了"。回报呈现中，在"期间的问答"里列出：

text
```text
     · 它问（10月1日 14:02）：…
       （它没等答复就结束了）
```
```
 这样她能看出帮手可能自己做了假设。
```

3\. **重复提问：**

- 先按阶段 0 做零调用诊断；
- 原因若在帮手池（例如同一次提问被发布了两次、送达的答复格式帮手认不出），就在 `Execution/pool.py` 里修掉；
- 原因若是帮手自己又问了一遍，就只靠附录 C 的提示修改；
- 原因若需要改 Execution V2，就不修，只写进报告。

4. **默认工作区：**&#x20;
   - 阶段 0 检查 WSL 里的 Docker；
   - 检查通过，R1 就用仓库默认的 `workspace/`；
   - 检查不通过，R1 记为"未验证（环境）"，R3 原话情景改用 B2 的临时目录做法，并在报告里标注清楚。
5. **主动说话的长度：**&#x20;
   - 本补丁不改；
   - 试用时由仓库主人观察。
6. **分支、提交与推送：**&#x20;
   - 在本地 `organs` 上继续开发，开始前确认工作树干净，并与 `origin/organs` 一致；
   - **永远不要**把 `organs-b` 合并、变基或 cherry-pick 进来；
   - **每个阶段结束各提交一次**；
   - 每次提交前检查暂存区，规则与推送前检查相同；
   - **推送前检查**，范围是 `origin/organs..organs` 的全部新提交：&#x20;
     - 路径中不能出现 `.env.local`、`data/`、`workspace/`、`runs/`、`cache/`、评测原始材料；
     - 不能有匹配 `sk-[A-Za-z0-9]{20,}` 的字符串，也不能有与本机真实密钥相同的值；
     - 不能有超过 50 MB 的文件；
     - 发现问题就停止推送并报告，不改写已推送的历史；
   - 检查通过后，普通快进推送到远端 `organs`，不强推；
   - 本卡放在 `docs/TASK_organs_b2_patch.md`；结果写进 `docs/RESULTS_organs_b2_patch.md`。两份都随代码进 `organs`，并照旧通过隔离 worktree 推到 `Execution_lab2`。
7. **模型预算：**&#x20;
   - 确定性测试和 Docker 测试零真实调用；
   - 真实调用合计不超过 **50 次**，Mind 和帮手都算在内，失败的尝试也算；
   - 达到上限就停下，保留现场并报告；
   - 全部使用当前配置的模型。

## 约束

- **数据与凭据：** 保护 `.env.local`、密钥、`data/`、真实 Hot/Cold/记忆库，禁止提交。测试全用临时目录；真实情景使用隔离的 Hot/Cold/SQLite，不读写真实记忆库；
- **git 安全：** 禁止 `git add -A`、`git clean -x`、`git stash -u`、`git stash -a`，只按路径暂存。不强推，不改写任何远端分支；
- **运行环境：** 用 `Conversation_Memory/.venv/bin/python`；保留 `.venv` 与 BGE-M3 缓存，不要删除或移动；
- **测试基线：** 改动前记录 `pytest -q`、`pytest tests -q`、`pytest Execution -q` 和实验室离线测试四套基线，验收时不能有新增失败；A1 逐字节一致测试必须通过；
- 服务仍然单进程（`--workers 1`）。在 Windows 上没验证过的部分，照实写明。

## 阶段 0：准备、环境检查与诊断（零模型调用）

1. 确认分支状态，记录四套基线；
2. **Docker 检查：**&#x20;
   - 在 WSL 里运行 `docker version`，应能看到 Client 和 Server；
   - 用仓库默认的 `workspace/` 做一次挂载检查：容器能只读看到测试文件，写入被拒，网络被禁；
   - 结果写进报告。检查用的测试文件，用完从 `workspace/` 移到仓库外的本地存档；
3. **重复提问诊断：** 读 B2 本地运行材料（`/tmp/lumina-organs-b2/real/` 或其备份）中 R2 两次的帮手事件日志。对每一次重复提问说明：&#x20;
   - 第一次提问后，帮手是否进入了 `Wait("MIND_REPLY")`；
   - 答复是否送达，帮手看到的答复是什么样子；
   - 第二次提问来自哪一次决策：是同一次提问被重放或被发布了两次，还是帮手新做的决定；
4. **过时提问诊断：** 读 R5、R6 的记录，说明她去答复已结束帮手的经过：提问和交回的时间先后，帮手问完之后是否等待；
5. 材料如果已经不在，照实写明；
6. 提交。
